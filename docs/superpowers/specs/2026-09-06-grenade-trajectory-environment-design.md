# グレネード軌道プレビューの環境係数・バリア連動 設計書

日付: 2026-09-06

## 課題

右クリック長押しで表示されるグレネードの弾道プレビュー（赤い点線と×マーク）において、
グレネードが水中に落ちた際にプレビューの軌道と実際のグレネードの軌道が大きく乖離していた。

### 原因

1. **実体（`Grenade.js`）**:
   毎フレーム `motionFor(game, x, y)` を取得し、水中の物理法則（`WATER_SPEED_SCALE = 0.5`, `WATER_GRAVITY_SCALE = 0.25`）に従って速度と重力をスケールさせている。
2. **プレビュー計算（`CombatActions.js: _calcGrenadeTrajectory`）**:
   環境係数を一切参照せず、ハードコードされた空気中（陸上）の物理定数（speed=1, gravity=1）のまま 90 フレーム先まで計算していた。
   そのため、水面突入後の減速や浮力がプレビューに反映されず、実際の着弾点とプレビューの着弾点（×マーク）がずれていた。
3. **定数の重複**:
   `Constants.js` の `GRENADE_*` を使わず、ローカルに `TRAJ_*` として同じ値をハードコードしていた。
4. **バリア（要塞ステージ）の未考慮**:
   電磁パルスバリアに突入したグレネードは吸収されて消滅するが、プレビュー線はバリアを素通りして奥まで描画されていた。

## 方針（設計上の決定事項）

1. **`motionFor(this, x, y)` の適用**:
   `_calcGrenadeTrajectory` 内のシミュレーションループにおいて、各ステップの座標 `(x, y)` で `motionFor(this, x, y)` を取得する。
   * 重力加算: `vy += GRENADE_GRAVITY * motion.gravity;`
   * 移動距離: `x += vx * motion.speed;`, `y += vy * motion.speed;`
   * 壁・床の跳ね返り時の移動距離補正にも `motion.speed` を反映。
2. **定数の統一**:
   `Constants.js` から `GRENADE_GRAVITY`, `GRENADE_MAX_FALLING_SPEED`, `GRENADE_BOUNCE`, `GRENADE_FRICTION`, `GRENADE_LIFETIME` をインポートして使用する。
3. **バリア吸収の反映**:
   `this.barriers` が存在し、計算中の座標がアクティブなバリア領域（`fieldRect`）に入った場合は、そこでシミュレーションを終了（着弾・消滅）とする。

## 期待される挙動

* 陸上・空中では従来通りきれいな放物線を描く。
* 水面（地底湖など）に突入した瞬間、点線の間隔が詰まり（減速）、浮力で緩やかに落下するリアルタイムの軌道が描画される。
* プレビュー終端の×マーク（`landX`, `landY`）と、実際に投げたグレネードの静止・爆発地点が完全に一致する。
* 要塞ステージのバリアに向かって投げた場合、バリア面でプレビュー線が止まる。
