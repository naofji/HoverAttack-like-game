# 雪の床を全員に共通化する（滑り・雪煙）

2026-09-20

## きっかけ

実機で「5面で母艦の甲板の上に立ったときに滑る・雪が舞う」。甲板は鉄板なので
おかしい、という指摘から始まった。

調べると、直すべきは甲板の特別扱いではなく **床の性質の持ち方**だった。今は
「面が雪なら、どこに居ても雪」になっていて、立っている対象を見ていない。
ユーザーの整理はこうである:

> 「すべる」ことの方が例外的な条件。通常は滑らないけど、5面で雪が積もった
> 地面の上にいるときだけ滑る。
> 雪の上で滑るのは敵のアタッカーもタンクもプレイヤーも同じ。

## 現状（実装を読んだ結果）

`motion.slide` を読んでいるのは自機と敵戦車だけで、3者の作りがばらばらである。

| | 横移動の決め方 | 摩擦の掛かる場所 | 雪で滑るか | 雪煙 |
|---|---|---|---|---|
| 自機 | 入力中は `vx = ±PLAYER_MAX_SPEED`、離すと減衰 | `_updateHorizontal` の `vx *= motion.slide` | 滑る | 出す（`_kickSnow`） |
| 敵アタッカー | AI が毎フレーム `vx` を**直接代入**（`vx = zigzagPhase * maxSpeed` など） | **無い**（前フレームの速度が残らない） | 滑らない | 出さない |
| 敵戦車 | 巡回・追跡で `vx` を代入 | 無い（階段の下り加速だけ持つ） | 平地では滑らない | 出す |

接地のさせ方も3者で違う。

| 接地させる場所 | 自機 | 敵アタッカー | 敵戦車 |
|---|---|---|---|
| 地形（タイル） | `_landOnMapOrHitCeiling` / `_probeGroundBelowFeet`（2か所） | 着地・足元プローブ（2か所） | `_collidesWithMap` |
| 母艦の甲板 | `_landOnCarrier` | — （甲板には乗らない） | — |
| 他のエンティティの頭 | `_landOnEnemy` / 足元プローブの敵判定 | `_checkVerticalEntities` | — |

**症状の原因はここにある。** 滑りも雪煙も「環境が雪か」だけで決めており、
地形の上なのか甲板や敵の頭の上なのかを誰も見ていない。

## 設計

### 1. 床の性質は1か所（`src/js/utils/surface.js` を新設）

```
groundSlide(entity, game)   → 0〜1
approachVx(entity, desiredVx, slide) → number
```

- `groundSlide` は **「接地していて、その接地面が地形で、その場所の環境が滑る床」**
  のときだけ `motion.slide` を返し、それ以外は 0 を返す。甲板・敵の頭・空中は 0。
- `approachVx` は滑る床での速度追従。`slide` が 0 なら目標速度をそのまま返す
  （＝今の陸上と完全に同じ）。0 でなければ前フレームの速度を `slide` の割合だけ
  残して目標へ寄せる。

この2つだけが「氷の上でどう動くか」を知っている。AI と入力は「どう動きたいか」
（`desiredVx`）を書くだけになる。泥・砂のような床を足すときも、
`StageEnvironment` の `motionAt` に1行足せば3者すべてに効く。

### 2. 接地面の種別を各エンティティが持つ

`onGround` を立てている場所はすでに列挙できているので、**地形が立てた場合だけ**
`onTerrain = true` を併せて立てる。`onGround = false` に戻すのと同じ行で
`onTerrain = false` に戻す（既存の `onGround` と同じ寿命なので、読む側は
前フレームの値を見るという既存の約束もそのまま）。

- 自機: 地形の2か所で true、甲板・敵の頭では false
- 敵アタッカー: 地形の2か所で true、`_checkVerticalEntities`（他機の頭）では false
- 敵戦車: `_collidesWithMap` の結果がそのまま地形接地

### 3. 空中には手を出さない

**これは踏んではいけない罠として明記しておく。** `Player._probeGroundBelowFeet`
（`Player.js:642`）と `_applySnowSlope` は、**空中のフレームで `motion.slide > 0`
であること**を条件に雪の階段の吸着（踏み外した直後に次の段へ吸い付く、段を跳ねない）
を行っている。空中まで「滑らない」にするとこの吸着が死に、1段16pxの落下を
10フレーム待つ以前の動きに戻る（`Player.js` のコメントに実測が残っている）。

したがって `groundSlide` が 0 を返すのは**接地しているとき**の話で、階段まわりの
判定は今までどおり `motion.slide`（＝面の性質）を見る。

### 4. 各エンティティの変更

- **自機**: `_updateHorizontal` の `vx *= this.motion.slide` を
  `groundSlide()` の値に差し替える。**操作感は変えない** ── 入力中は今までどおり
  即座に最高速へ（氷でも加速が鈍くならない）。ユーザーが慣れた操作なので、
  今回の「敵も滑る」に巻き込んで変えない。
- **敵アタッカー**: `_updateMovement()` が決めた `vx` を目標速度とみなし、
  そのフレームの最後に `approachVx` を1回通す。AI の各分岐（chase / patrol /
  zigzag / 回避 / ダッシュ）には手を入れない。ダッシュ（`RIVAL_DASH_*`）は
  目標速度を上げるだけなので、氷の上では立ち上がりが鈍り、止まるのに時間がかかる。
- **敵戦車**: 同じく `approachVx` を1回通す。既存の階段加速はそのまま残す。
- **雪煙**: 自機・戦車の既存の条件（接地＋速度）に `onTerrain` を加える。
  アタッカーにも同じ条件で出す（3者で床の扱いが同じになる、という今回の趣旨）。
  粒は戦車と同じく**画面内のみ**（画面外で撒くと particles を食い潰す。
  `docs` の view-cull の実測がある）。

### 5. 非目標

- 飛行する敵（ドローン・ミサイル）は接地しないので対象外。
- 水・滝の床は今回触らない（`slide` は 0 のままで、この設計に素直に乗る）。
- 自機の**加速**の鈍化は入れない（上記のとおり操作感を守るため）。

## バランスへの影響と、その測り方

敵が止まれない・曲がれないということは、**崖や水へ滑り落ちる**ことがある。
実装後、実物の Map を使って次を数え、報告してから採否を決める。

- 5面の敵アタッカー・戦車を N 体 × 数千フレーム動かし、
  「自分から落下した回数」「穴・水に落ちて死んだ数」を変更前後で比較する
- 併せて「自機との距離の分布」（張り付きすぎ・離れすぎになっていないか）

数値が荒れた場合の逃げ道は、敵だけ係数を下げること。`ICE_SLIDE` を自機用と
敵用に分けられる形で実装しておく（既定は同値）。

## テスト

- `groundSlide`: 雪＋地形接地でだけ非0。甲板・敵の頭・空中・陸上の面では 0
- `approachVx`: `slide=0` は目標速度そのまま（陸上の現行挙動と一致）。
  非0では前フレームの速度が残る／目標へ単調に近づく
- 自機: 甲板の上で即停止・雪煙なし、雪の地形では従来どおり滑る
- 敵アタッカー: 雪の地形で目標速度に届くまでに時間がかかる／陸上では1フレームで届く
- 敵戦車: 同上、階段の下り加速が残っている
- 回帰: 既存の雪テスト（階段の吸着・くの字・雪煙の種類）がそのまま通ること
- 変異チェック: 「甲板でも滑る」「空中で滑りを切る」の2つを入れて赤くなることを確認
