# タイル形状つき当たり判定 — 設計

日付: 2026-10-27。ユーザー承認済み。

## 1. なぜ作るか

5面（雪の洞窟）で**見た目と当たり判定が一致していない**。

- 宙に浮いた2ブロックの板は、絵では両端がくの字（`Map._drawRockyBlock` の chevronL/R）だが
  判定は正方形タイル2つ。片方を壊すと、残ったタイルの絵と判定が食い違って見える。
- 雪の階段は、描画オフセット（`utils/slope.js` の `slopeDrawOffset` / `plateDrawOffset`）で
  機体の絵だけを斜辺へ下げ、判定は階段のまま。壊せる地形ではこの特例で吸収しきれない。

描画の特例を積み増すのをやめて、**タイルそのものが形を持ち、絵と判定がその形を共有する**仕組みに作り直す。
仕組みは**全部の面で共通**にし、面ごとに違うのは「形を決める規則」だけにする（ユーザーの決定）。

## 2. ゴール／ゴールでないもの／失敗とみなすもの

**ゴール**
- 5面では、生成直後も、ブロックを壊した後も、**絵の輪郭と判定の輪郭が常に一致する**。
- 5面の階段は本物の45度の坂になり、壊して段差ができてもその場で坂・面取りに変わる。
- 斜面で、自機・戦車・敵アタッカーは今の雪の階段と同じ感触で上り下りし、弾・グレネードは斜面の向きで跳ね返る。
- 仕組みは全面共通。将来ほかの面に斜面を足すときは規則の差し替えだけで済む。

**ゴールでないもの**
- 5面以外の見た目・手触りを変えること（四角は四角。角を丸く削る絵も今のまま、判定も四角と同じ結果）。
- 水・敵の湧き位置・破片・薬莢・アイテムの判定を形つきにすること（タイル単位のまま。形が空でないタイルは岩）。ただし地面に乗るものの**置く高さ**は形に合わせる（決定12）。
- 45度以外の角度、半タイルより細かい形。

**失敗とみなすもの（技術的に動いても駄目）**
- 5面以外で、何かの挙動が変わる（同じ入力で同じ軌跡にならない）。
- 週次の決定性が壊れる（`tests/MapDeterminism.test.js`）。形の計算で `game.rng` を消費しない。
- 斜面の上で機体が引っかかる・震える・すり抜ける・宙に浮いて見える。
- フレーム落ち（描画は予算の8.4%で余裕があるが、判定は毎フレーム多数回呼ばれる）。

## 3. 決まっていること（ユーザーの決定）

1. **タイルを4象限（各8px×8px、タイルは16px）に分け**、各象限は「満ち」「空」「45度の三角（4向き）」のどれか。
   タイルの形はこの4つの組。
2. 浮いた2ブロックの板は「<==>」（左タイル「<=」、右タイル「=>」、合わせて六角形）。
   左を壊すと、右は位置を変えずに**単独タイル＝菱形「<>」**になる。
3. **絵と判定は同じ形を共有する。** `slopeDrawOffset` / `plateDrawOffset` の描画オフセットは廃止する。
4. **形は周囲のブロックの並びから自動で決まる。ブロックが壊れたら周りのタイルが形を作り直し、5面では新しい斜面ができる。**
5. 斜面を使うのは今のところ5面だけ。5面は**段差を作らず、端はすべて斜面か面取り**にする。
   5面以外は見た目も判定も今までどおり四角。
6. 形を判定に使うのは、**自機・戦車・敵アタッカー（地面を動くもの）と、弾・グレネード**。
   水・湧き位置・破片・薬莢・アイテムはタイル単位のまま。
7. 斜面の挙動は今の雪の階段と同じ。**押し続ければ上れる、離すとずるずる滑り落ちる。**自機・戦車・敵アタッカー共通。
8. 5面の `carveSnowStairs` が盛る階段は、**斜め半分のタイルを並べた本物の45度の長い坂**に置き換える。
9. 床の縁・崖の上の角など、段が続かない角は**小さい面取り（8px）のまま**でよい。
10. **反射ビームと跳弾は、斜面の向き（斜辺の法線）で斜めに跳ね返る。**
11. **空中で斜面に当たったら、斜面に沿って滑る。** 横に飛んで坂に当たれば上へ逸れ、天井の斜面に当たれば斜面に沿って流される
    （今の「縦・横の軸ごとに止まり、1段なら乗り上げる」ではなく、斜辺の法線方向へ押し出して接線方向の動きを残す解き方）。
12. **地面に乗っていて形を使わないもの（アイテム・地雷・砲台・基地・母艦など）は、地形の形に合わせて置き直す。**
    判定はタイル単位のままでよいが、坂や面取りの上で描いた地面から浮いて見えないよう、置く高さ（と必要なら傾き）を床の高さの問い合わせから決める。
    ブロックが壊れて下のタイルの形が変わったときも追従する。配置の場所（どのタイルに置くか）は今のまま変えない＝敵の構成は不変。

## 4. 形を決める規則（5面）

ここは**私の判断**（ユーザーには上の決定9までを確認済み。規則の細部は未確認）。

- 形は「岩か空洞か」のグリッドだけから決まる純関数にする（乱数を使わない）。
- 4つの角それぞれについて、その角をはさむ2辺（例: 左上なら上と左）が**両方とも空洞**なら、その角を削る。凹角（内側の角）は削らない。
  - その角の斜め向こうへ**段が続いている**（例: 右へ上る階段で、左上の角の左下の隣が岩で、その上が空洞）なら、
    **タイル1枚ぶんの斜め（16px、対角線で半分）**にする。並べると途切れのない45度の坂になる。
  - 段が続かなければ**小さい面取り（8px、その象限だけ三角）**にする。
- 検算: 単独タイル→4角とも小さい面取り→菱形 ✓。2ブロックの板→外側の2角ずつ→「<=」「=>」✓。床の縁→上の角だけ小さい面取り ✓。
  1段ずつの階段→各段がタイル1枚ぶんの斜め→45度の坂 ✓。
- 天井側（下の2角）も同じ規則で削る（上下対称）。
- 今の `_drawRockyBlock` の特例（`rampTL/TR`、`chevronL/R`）と `utils/slope.js` の `stairDirection` / `plateTipDirection` は、この規則に吸収されて不要になる見込み。
- **磨き仕上げのブロック（外周の `BLOCK_INDESTRUCTIBLE`、基地まわりの `BLOCK_METAL`。`_drawPolishedBlock` で描くもの）は5面でも削らず四角のまま**（私の判断。基地の枠と外周は人工物で、四角に描かれている）。隣の岩から見れば「岩」として数える。
- 5面以外の規則は「常に四角」。今の角を丸く削る絵は**描画だけの装飾**として残す（判定は四角）。

**生成で段差を作らないことは、この規則で保証する（私の判断）。** 部屋や通路の彫り方には手を入れない。
生成直後の段差も壊してできた段差も同じ規則で坂・面取りになるので、仕組みが1本で済み、敵の配置や週次の決定性にも触れない。
`carveSnowStairs` は今と同じく「滑れる長さの1段ずつの段」を盛るだけでよく、規則がそれを坂にする
（決定8の「置き換え」は、こうして段を坂として扱うことで実現する。盛る段の並びが今と同じなら乱数の消費も変わらない）。

## 5. 判定の問い合わせ

- `Map.isSolid(r, c)` は「タイルのどこかに岩がある」の意味で残す。呼び出しは約30ファイル・約130か所あり、
  水・湧き位置・破片などはそのまま使い続ける（決定6）。
- 形を見る問い合わせを新しく足し、決定6の相手（自機・戦車・敵アタッカー・弾・グレネード・反射ビーム・跳弾）だけをそちらへ移す。
  必要になりそうなもの: 点が岩の中か／矩形が岩に重なるか／ある x での床の高さ（と斜面の向き）／線分が当たる位置とその面の法線。
  名前と分け方は builder に任せる。
- 形はタイルごとに表へ焼いておき、ブロックが壊れたら**壊れたタイルの周り（3×3）だけ**作り直す。
  判定のたびに周囲を見て計算し直さない（[[one-level-one-definition]] の教訓: 要約値は1か所に焼いて全員に読ませる）。
- 5面以外の面では、新しい問い合わせが今の四角の判定と**ビット単位で同じ結果**を返すこと。テストで縛る。

## 6. 動くものの挙動

- **自機・戦車・敵アタッカー**: 機体の体（足だけでなく横・頭も）を形で当てる。坂では「押し続ければ上れる、離すと滑り落ちる」（決定7）。
  今の雪の階段の作り（`Player._probeGroundBelowFeet` の吸着、`utils/surface.js` の `groundSlopeDirection`、`EnemyTank` の対応）を、
  階段ではなく斜面の形の上で動くように一般化する。描画オフセットは廃止（決定3）。
- **弾**: 形で当てる（斜面の削れた部分は素通りし、斜辺で止まる）。ここで言う「弾」は**地形に当たる飛び道具すべて**とする（私の判断。ゴールの「絵と判定が常に一致」から）。`Bullet` を継ぐ自機・敵の弾に加え、自機の `Missile`、`EnemyHomingMissile`、`EnemyCruiseMissile`、`BaseLaser`、ドローンの地形の判定も移す。5面の足場を削るのは主に敵のミサイルなので、ここを外すと面取りの空中で爆発する。
- **反射ビーム・跳弾**: 斜辺の法線で反射する（決定10）。`utils/beamPath.js` の「元の位置から新しい速度で動かす」作りは保つ。
- **グレネード**: 斜辺の法線で跳ね返り、坂の上では下へ転がる（**私の判断**。反射ビームと揃えた）。
- **空中の機体**: 斜面に当たったら斜辺に沿って滑る（決定11）。自機の `_moveHorizontalIntoMap` の「横→縦の順に解き、1段なら乗り上げる」は、5面以外で今と同じ結果になることを保ったうえで、形に対する押し出しに置き換える。角（面取りの頂点）で震えないこと。
- **地面に乗るもの**（アイテム・地雷・砲台・基地・母艦など）: 置く高さを床の高さの問い合わせから決める（決定12）。どれを対象にするかの洗い出しは builder に任せる。
- 薬莢・破片・水・湧き位置: 変更なし。

## 7. 描画

- 5面は、タイルの形（4象限）からそのまま輪郭の多角形を作って描く。雪のふち（`SNOW_CAP_COLOR`）も斜辺に沿わせる。
- 形が作り直されたタイルは、描画のキャッシュも作り直す（[[lazy-cache-every-writer-notifies]]: 地形を書き換える処理は必ず通知を通す）。
- 5面以外の描画は変えない。

## 8. 制約

- バニラ ES modules、ビルドなし、依存なし。数値は `Constants.js`（斜面の加速・吸着など。初期値は builder が決め、実機でユーザーが調整する）。
- 週次の決定性を守る。形の計算で乱数を使わない。
- テストは `node --test`。ソース文字列を grep するテストは書かない。テストは壊すと赤くなることを確かめる。
- 5面以外の挙動が変わらないことは、今の当たり判定との比較（同じ入力で同じ結果）で示す。
- 5面の手触りが変わるので、同じ週のスコアが比べにくくなる。**本番への反映（main への push）はユーザーが時期を決める**（私の判断。週の切り替わりに合わせるのが無難と引き渡し時に伝える）。コード側の手当ては作らない。
- 実機の確認はユーザーが行う。引き渡すときは確認ポイントと調整用の定数の対応表、ハードリロード（Cmd+Shift+R）が要ることを伝える。

## 9. builder に任せること

- 形の表現（4象限の組の符号化）、問い合わせの名前と分け方、表の持ち方。
- 斜面の滑り方・吸着の定数の初期値。
- 段の分け方。自然な順序は「形の規則と問い合わせ（5面以外で同一の証明つき）→ 自機・戦車・アタッカー → 弾・ミサイル・グレネード・反射 → 地面に乗るものの置き直し → 5面の描画の置き換えと旧特例・描画オフセットの撤去」。
- 5面の雪の木・つららなど背景の建物が、面取りされたタイルの上で浮いて見えないようにする置き方の調整。
