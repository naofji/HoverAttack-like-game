# 死亡ホールド演出（Death Hold）

日付: 2026-08-05

## 目的

自機（Player）と母艦（Carrier）が破壊されたとき、破壊演出を見せる間もなく視点が切り替わってしまう。
破片の飛散演出（`2026-08-05-destruction-debris-design.md`）を追加したことで、この問題が顕在化した。

破壊された瞬間に一定時間の**ホールド**を挟み、その間はカメラを撃破地点に留めて、
リスポーンもゲームオーバー遷移も行わないようにする。

## 現状の挙動

| 対象 | 現状 |
|---|---|
| 自機（残機あり） | 死亡した次の tick で母艦上にリスポーンし `docked` になる。`_updateCamera`（`main.js:626`）は `docked` の自機を追わないため、カメラの追従対象が母艦へ即座に切り替わる |
| 自機（残機ゼロ） | `_triggerGameOver()` が即座に走り、BGM 停止・GAME OVER 表示 |
| 母艦 | `CARRIER_INITIAL_LIVES = 1` のため、破壊は常に残機ゼロ。即ゲームオーバー |

## 決定事項

1. **ゲームオーバー遷移も遅らせる。** 母艦の破壊は常にゲームオーバーなので、
   遅らせなければ母艦だけ演出が見えないままになる。自機・母艦のどちらで死んでも見え方が揃う。
2. **ミッションタイマーは回したままにする。** 死亡はもともと損であり、1.5 秒弱の追加は誤差の範囲。
   タイマーの進む条件を増やさないほうが単純。
3. **シミュレーションは止めない。** 破片が飛び続けることがこの演出の目的。
   敵・弾・破片・地形はすべて通常どおり進む。
4. **止めるのは3つだけ** — リスポーン、カメラの追従対象の切り替え、ゲームオーバー遷移。

## 設計

### 状態

ホールドの状態管理は `src/js/systems/DeathHold.js` に切り出す。

`main.js` は DOM に依存しておりテストから import できない。ロジックを `main.js` に直書きすると
一切テストできないため、独立したモジュールに置く（`trimDebris` を純関数に切り出したのと同じ理由）。

```js
class DeathHold {
    constructor(frames)   // ホールドの長さ（tick）
    get active()          // ホールド中か
    get focus()           // カメラに渡すフォーカス点 {x, y, width, height}。非ホールド時は null
    begin(x, y)           // 撃破地点を指定してホールド開始。既に active なら何もしない
    tick()                // 1 tick 進める。この tick で明けたら true
    clear()               // 即座に解除（ステージ切り替え時）
}
```

`focus` が `{x, y, width, height}` を返すのは、`Camera.follow()` がエンティティを受け取り
`x + width / 2` で中心を求めるため。幅・高さ 0 の点を渡せば、その座標が画面中心になる。

### main.js の配線

- `_updatePlayer` / `_updateCarrier`: 対象が `!alive` になったとき、`deathHold.active` でなければ
  `begin(cx, cy)` を呼ぶ。`active` の間はリスポーンもゲームオーバーもしない。
  明けた tick で従来どおりの分岐（残機があればリスポーン、なければゲームオーバー）を実行する。
- `_updateCamera`: `deathHold.active` なら `camera.follow(deathHold.focus)` を優先する。
- `GameStateManager.resetLevel`: `deathHold.clear()` を呼ぶ。

### エッジケース

- **自機と母艦がほぼ同時に壊れた場合** — 先に立ったホールドを維持し、フォーカスも最初の撃破地点のまま。
  2つ目で上書きすると視点が飛んで本末転倒になる。`begin()` が `active` 中の呼び出しを無視することで実現する。
- **ホールド中の追加ダメージ** — 対象は既に `alive = false` なので、各 `takeDamage` の
  先頭ガードで無視される。新たな考慮は不要。
- **ホールド中のミッションクリア判定** — 自機が死んでいるため旗は取れない。従来どおりで問題ない。

### 長さ

`DEATH_HOLD_FRAMES = 90`（60fps で 1.5 秒）。破片の寿命が 55〜75 tick なので、
破片が消えきるところまで見える。NORMAL モードでは tick が 0.8 倍速で進むため実時間では
1.25 倍長くなるが、これはゲーム全体が同じ性質なので統一が取れている。

## テスト方針

`DeathHold` を独立モジュールにしたことで、状態遷移そのものは直接テストできる。

- `begin()` で `active` になり、`focus` が撃破地点を指す
- `active` 中の `begin()` は無視され、フォーカスが上書きされない
- 規定 tick 数ぶん `tick()` を回すと、ちょうどその tick で `true` を返して解除される
- 解除後は `active` が false、`focus` が null
- `clear()` で即座に解除される
- 非 active 時の `tick()` は `false` を返し、副作用がない

`main.js` の配線（リスポーン抑止・ゲームオーバー抑止・カメラ切り替え）は import できないため、
`DeathHold` の契約テストで担保する。

## スコープ外

- 敵機の破壊ではホールドしない（テンポが落ちるため）
- ホールド中の演出的な追加（スローモーション、画面効果など）は行わない
