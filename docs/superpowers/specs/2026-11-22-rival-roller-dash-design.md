# rival のローラーダッシュ 設計

2026-11-22

## 目的と理由

5面から出る赤い rival に、装甲騎兵ボトムズのローラーダッシュ（脚を踏み出さず、
足の車輪で地面を滑って走る）をさせる。ユーザーの狙いは **見た目の格好よさ＋動きの
読みにくさ**。

使い所はユーザーの案で **自機から距離を取るために後退するとき**。滑っている間は
地上を直線で動くので狙われやすい ── だから常用せず、使う場面を絞る。
滑っている間も **撃つ**（ユーザー決定。推奨は「撃たない」だったが、ボトムズらしさと
手強さを取った）。

## 目標 / 非目標 / 反目標

- 目標: 近づかれた rival が、自機の方を向いたまま後ろへ高速で滑って距離を取り、
  撃ちながら下がり、火花を散らして急停止する。どこで止まるかが読めない。
- 非目標:
  - 既存の「照準が合ったら横へ瞬間加速する」回避ダッシュ（`RIVAL_DASH_*`、
    `_updateAlignmentAvoidance`）は**変えない**。役割が違う（横へ消える／後ろへ滑る）。
  - rival 以外の型、自機には付けない（表の1行で付けられる形にはしておく）。
- 反目標（動いても失敗）:
  - 滑りっぱなしで rival が近づけない＝近接戦が成り立たない。連発させない。
  - 空中で滑る、壁に向かって滑り続ける、崖から勝手に落ち続ける。
  - 他の型（standard / heavy / artillery）の挙動が1フレームでも変わる。

## 制約

- CLAUDE.md の表の流儀: 型ごとの違いは `ENEMY_ATTACKER_TYPES` の行に出す。数値は全部
  `Constants.js`（`ROLLER_*`）。描画専用の形の数値だけは `legs.js` のモジュールスコープ可。
- `EnemyAttacker.js` 本体には挙動を書かない。`update()` に呼び出しを足す必要があれば
  1行だけ。
- 音は Web Audio の手続き合成。`AudioManager.js` 本体に書かず `audio/sounds/enemySounds.js`。
  A特性で既存の音（`playRivalDash`）との相対 dB を実測してテストで縛る。
  `play*` は引数なしで呼んでも例外を投げない。
- 週次の決定性: AI の判断は既存の movement と同じく `Math.random` を使ってよい
  （マップ生成の `game.rng` には触らない）。
- 地形の解き方は `walkerBody.js` / `slopeBody.js` の共通部品に任せる（段差の乗り上げ・坂）。
  ここに別の地形処理を書かない。

## 作り方の比較（採用: A）

- **A. 新しい層ファイル `entities/attacker/rollerDash.js`（採用）** — 始める判定・滑り・
  急停止・火花を1か所に。`Object.assign(EnemyAttacker.prototype, ...)`。名前の重なりは
  既存の mixin テストの仕組みで見張る。表の1行で他の型にも付けられる。
- B. `movement.js` の `zigzag_chase` に直書き — 早いが、550行の中で乱数とジグザグが
  入り組んだ箇所がさらに読みにくくなる。
- C. 雪面の滑り物理（`motion.slide` / `approachVx`）で初速＋摩擦 — 自然だが「どこで
  止まるか」を操れない。読みにくさの肝が作れない。雪面で二重に滑る。

## 決めたこと（ユーザー決定）

1. 対象は rival。型の行に `rollerDash: true`。
2. 使う場面は **自機から距離を取る後退**。
3. 滑っている間も撃つ。射撃の間隔はふだんどおり（`_handleShooting` は変えない）。
4. 向きは自機の方のまま（追跡中の既存の `_updateFacing` がそうしている）＝後ろ向きに滑る。
5. 実装は A。

## 挙動（Claude の提案。会話で示した案を細かくしたもの。ユーザーの承認はこの設計書で取る）

### 始める条件（すべて満たす）

- `config.rollerDash` が真、`aiState === 'chase'`、`onGround`
- `zigzag_chase` の「近すぎる」分岐に入った（`absDx < preferredDist - 20`、今は 60px）
- クールダウン（`rollerCooldown`）が 0、反動中でない、回避（`evadeTimer`）中でない
- 狙う相手は `_getClosestTarget` の返す相手（自機がドッキング中なら母艦）。母艦から
  離れるときにも使う。**Claude の判断**: rival は母艦にも同じ距離感で戦っているので、
  相手で分けると条件が1つ増えるだけで得るものがない
- 後ろ（逃げる側）の足元に床がある — 1タイル先を `isSolidAtPixel` で見る。
  無ければ始めない（崖へ飛び出すのは反目標）
  - **Claude の判断**: 崖の確認は始めるときの1回だけ。滑っている途中に床が尽きたら
    下の「途中で終わる」に任せる

### 滑り方（フレーム単位）

状態は `rollerTimer`（その相の経過フレーム）と `rollerPhase`（`'accel'|'glide'|'stop'`）と
`rollerDir`（-1/+1、自機から離れる向き）。

- 長さは始めるときに `ROLLER_GLIDE_FRAMES_MIN..MAX` から乱数で決める
  ＝これが「どこで止まるか読めない」の正体。
- accel: `ROLLER_ACCEL_FRAMES` で 0 → `ROLLER_SPEED` へ線形に上げる
  （止まった状態から一気に乗る。既存の回避ダッシュの「線形に戻す」と対の作り）
- glide: `ROLLER_SPEED` で一定。
- stop: `ROLLER_STOP_FRAMES` で `ROLLER_SPEED` → 0 へ。始まった瞬間に急停止の火花と音。
- 終わったら `rollerCooldown = ROLLER_COOLDOWN`。

初期値の案（実機で調整する前提。根拠もコメントに残す）:

| 定数 | 案 | 根拠 |
|---|---|---|
| `ROLLER_SPEED` | 2.4 px/frame | 最高速 1.20 の2倍。残像のしきい値 1.6 を超えるので滑走中は尾が出る（意図どおり）。回避ダッシュの初速 3.6 より遅い＝「消える」ではなく「滑る」 |
| `ROLLER_ACCEL_FRAMES` | 6 | |
| `ROLLER_GLIDE_FRAMES_MIN/MAX` | 20 / 50 | 移動量はおよそ 60〜135px。近すぎ(60px)から推奨距離 80px の外まで確実に出る |
| `ROLLER_STOP_FRAMES` | 8 | |
| `ROLLER_COOLDOWN` | 240（約4秒） | 連発防止。近接戦が成り立つ間を残す |

滑走中は:

- `vx` を直接決める。**ジグザグとジャンプは止める**（`zigzag_chase` の後半の
  跳ぶ／吹かす処理を飛ばす）。
- **床の滑り（`_applyGroundSlide`）を通さない**。**Claude の判断**: rival が出るのは
  5面（雪・氷、`ICE_SLIDE` 0.94）からなので、通すと加速が16フレームほど鈍って
  「一気に乗る」が雪面で消える。車輪が噛んでいる扱いにする。段差の乗り上げは通常どおり。
- **坂**（`_applyAttackerSlope`）も通すが、上りの速さの上限は滑走の速さから取る:
  `rollerSpeedNow × SLOPE_UPHILL_SCALE`（2.4 なら 1.44）。**Claude の判断**。
  今の上限は `maxSpeed × SLOPE_UPHILL_SCALE`（rival は 0.72）で、そのままだと上り坂で
  歩きより遅く失速する。上限を計算しているのは呼ぶ側（`attacker/collision.js`）なので、
  共通部品の `slopeBody._applySlope` には触らない。「上りは平地の 0.6 倍」という
  自機と同じ規則は保つ。下りは既存どおり（加速して上限 3.0）。
- 回避（`_updateAlignmentAvoidance`）は始めない（ローラーダッシュが優先）。
  軸合わせのカウンタは数え続けてよい。

### 途中で終わる

- 足が地面を離れた（段差から落ちた・吹き飛ばされた）→ その場で終了。`vx` はそのまま
  持ち越し、空中は通常の処理に任せる。クールダウンは掛ける。
- 壁に当たって進めない（衝突で `vx` が 0 に潰された）→ その場で終了。崖のふちの踏みとどまりや
  機体どうしの当たりで止められた場合も同じ（`_reactToWall` を通らないので、前のフレームの `vx` が
  0 になっていたら終える）。
- 反動（`tickRecoil`）が入った → 終了。
- `aiState` が chase でなくなった → 終了。
- 上の4つはどれも **stop 相を経ずにその場で終わり、急停止の音と火花は出さない**。
  クールダウンは掛ける。急停止の演出は、決めた長さを滑り切って stop 相に入ったときだけ
  （壁や落下で止まったのに「キィッ」と鳴るのは不自然）。**Claude の判断**。

### 撃つ

`_handleShooting` は手を入れない。MG 持ちは standard だけなので rival はミサイル／
グレネード。`burstCount > 0` で足を止める既存の規則は rival には実質掛からない。

## 見た目

- **脚**: 滑走中は歩行アニメを止め（`walkFrame` を進めない）、両足を地面に着けたまま
  膝を少し曲げて前後に開いた「滑走の構え」で固定する。`legs.js` に滑走用の関節の組み方を
  足す（`_bipedWalkJoints` と同じ並びの関数）。形の数値は `LEG_STYLES` 側か同ファイルの
  モジュールスコープ。破片（`_collectLegPoses` を読む）も滑走中の姿勢になる ── 許容。
- **火花**: 足元（両足の接地点）から小さな火花。滑走中は数フレームおきに数粒、急停止の
  瞬間にまとめて多め。既存の `createSparks`（被弾の火花）は大きすぎるので、
  `SpawnEffects.js` に `spawnRollerSparks(x, y, count, dir)` を足し、粒は後ろ
  （進行と逆向き）に低く飛ばす。数・速さ・寿命・色は `ROLLER_SPARK_*`。
  画面外では出さない（`isInView`、雪煙と同じ理由）。
  - **雪の床の上では火花を出さない**。既存の雪煙（`_kickSnow`、`|vx|` がしきい値を
    超えると自動で出る）が代わりを務める。**Claude の判断**。
- **残像**: 既存のまま。速度 2.4 がしきい値 1.6 を超えるので自動で出る。

## 音

`audio/sounds/enemySounds.js` に2つ。位置つき（`_positionalGain`）で `playRivalDash` と同じ形。

- `playRollerDash(x, y, durationSec)` — 始めた瞬間に1回。決めた長さぶん鳴る
  単発音（車輪の唸り＋接地の擦れ。モーターの鋸波と帯域ノイズ）。
  **ループ音にしない理由**: 長さは始める時点で決まっている。ループにすると、面を離れる・
  撃破されたときの止め忘れ（memory: stage-only-loop-sound-leak）の面倒を全部抱える。
  途中で終わったとき（壁・落下・反動・撃破）は、`playRollerDash` が返す「止める関数」で
  短く抜いて止める（最終レビューで、全長ぶん1秒以上鳴り残ると分かったため）。
- `playRollerStop(x, y)` — 急停止の「キィッ」。短い高めの擦れ。
- 音量は A特性 `transientLevel` で `playRivalDash` との相対 dB を測ってテストで縛る。
  目安は唸りが回避ダッシュ音より控えめ（滑走中ずっと鳴るため）、急停止は同程度。

## テスト（node --test）

- 始める条件: 近すぎ＋接地＋クールダウン0で始まる／空中・クールダウン中・回避中・
  背後に床なし・`rollerDash` の無い型では始まらない。
- 速さの形: accel で線形に上がり、glide で一定、stop で 0 へ。長さが MIN..MAX に収まる。
- 滑走中はジャンプしない・ジグザグしない・回避が始まらない。
- 滑走中も射撃タイマーが進んで撃つ。
- 途中で終わる4条件。
- 雪の床で `_applyGroundSlide` を通らない（速度が即座に出る）。
- mixin の名前の重なり（既存の仕組みに rollerDash を足す）。
- 音: 引数なしで例外を投げない、A特性の相対 dB。
- 他の型が変わっていない: `node tools/trace-walkers.mjs` の指紋で standard / heavy /
  artillery が前後で一致することを確認（rival は変わってよい）。
  **注意**: 今の trace-walkers は全機体を1つの面に入れて1本のハッシュにまとめ、
  `Math.random` も全機体で共有している。rival が乱数を余分に引くと他の型の指紋も
  動いてしまうので、型ごとに別の走らせ方・別の指紋にする手直しを先に入れる
  （手直しの前後で、まだ何も変えていない状態の指紋が一致することも確かめる）。
- 坂: 上り坂で滑走の速さが `ROLLER_SPEED × SLOPE_UPHILL_SCALE` まで出る。

## 実機の確認ポイント（ユーザー）

近づいたときの滑る距離・速さ、止まる位置のばらつき、脚の構え、火花の量、音の大きさ、
近接戦が成り立つか（クールダウン）。対応表は実装後に渡す。
