# 破壊演出: 機体パーツの飛散（Destruction Debris）

日付: 2026-08-05

## 目的

機体が破壊されたとき、現在は「機体が消える」と「爆発パーティクルが出る」が同時に起きるだけである。
ここに、機体が**意味のあるパーツ単位で砕けて飛び散る**演出を加える。パーツは重力と慣性の影響を受け、
回転しながら徐々に小さくなって消える。

シューティングゲームの破壊の見せ場を強化することが目的であり、ゲームプレイには影響させない。

## スコープ

対象は6機体。

| 分類 | 対象 |
|---|---|
| 自軍 | Player、Carrier |
| 敵 | EnemyDrone、EnemyTank、EnemyTurret、EnemyAttacker |

**対象外**（今回は手を入れない）:

- EnemyBase — 既に多段階のパーツ破壊演出を持つため、本仕様の破壊表現が固まってから別途検討する
- AutoAimUnit、Landmine — 小物
- Missile、Grenade、EnemyCruiseMissile、EnemyHomingMissile — 爆発物であり破片は不要

## 決定事項

ブレインストーミングで確定した方針。

1. **パーツは手作業で定義する**。機体をオフスクリーン描画して機械的に切り刻む方式は採らない。
   目的が「意味のあるパーツ単位で壊れる」ことなので、どこで部品を切るかを人間が決められることに価値がある。
2. **破片にゲームプレイ上の当たり判定は持たせない**。ダメージも、ノックバックも、地形との衝突も行わない。
3. **破片は地形をすり抜ける**。重力と慣性で放物線を描き、地面には反応せず、縮小しながら消える。
   洞窟地形に破片が溜まらず、地形判定のコストも増えない。
4. **飛び始めのタメは機体ごとに変える**。雑魚は即分解、大物は一瞬の発光を挟んでから分解する。
   実装上はホールドフレーム数という単一の数値で表現し、A/B/C の演出差は数値の違いに還元する。
5. **可動部は死亡時のポーズを反映する**。固定パーツは静的テーブル、脚や砲身は現在の関節角度を焼き込む。

## アーキテクチャ

### 新規モジュール

| ファイル | 責務 |
|---|---|
| `src/js/entities/DebrisPart.js` | 破片1個。位置・速度・回転・寿命・縮小を保持して `update()` / `draw()` する。自分が何の部品かは知らない |
| `src/js/entities/debris/index.js` | `buildDebris(entity, kind)` — パーツ定義を引き、ローカル座標をワールド座標へ変換して `DebrisPart[]` を返す |
| `src/js/entities/debris/playerParts.js` 他 全6ファイル | 機体ごとのパーツ定義と演出パラメータ |
| `src/js/utils/Constants.js`（追記） | 重力・空気抵抗・寿命・同時存在数上限などの共通チューニング値 |

パーツ定義を機体クラスのファイル内に置かないのは、`EnemyAttacker.js` が既に 1410 行、`Player.js` が 771 行あり、
これ以上肥大させたくないため。

### 既存コードへの変更

- `main.js` に `spawnDebris(entity, kind)` を追加する（`spawnExplosion` の隣）
- 各機体の `die()` / `destroy()` に呼び出しを1行追加する（6箇所）
- 可動部を持つ4機体（Player、EnemyTank、EnemyTurret、EnemyAttacker）に `getDebrisParts()` を実装する

破片は `game.particles[]` に push する。`DebrisPart` は既存の `Particle` と同じ
「`update()` と `draw()` と `alive` だけを持つ」契約に従うため、毎フレームの更新（`main.js:641`）、
描画（`main.js:1070`）、ステージ切替時のクリア（`GameStateManager.js:39`）は既存経路がそのまま機能する。
ゲームループの構造は変更しない。

### パーツ定義の形式

```js
// 固定パーツ: 機体ローカル座標（各機体の draw() と同じ原点）の矩形
{ x, y, w, h, color, weight }
```

`weight` は飛び方の重さ。大きいほど初速が遅く回転も鈍い。胴体は重く、装甲板や砲身は軽く飛ばす。

可動部を持つ機体は `getDebrisParts()` を実装し、死亡時点の関節角度を焼き込んだ同形式の配列を返す。
既存の `Player._drawSingleLeg` / `EnemyAttacker._drawJointedLeg` が関節座標を計算済みなので、
その計算を切り出して描画と破片生成で共有する。

## 破片のライフサイクル

3つの局面を1つのクラスで通す。発光シルエット専用の描画経路は設けない。

### 局面1 — ホールド（0〜6フレーム）

パーツを元の位置に静止させたまま、白熱色へ寄せて描画する。パーツが元の配置のまま並んでいるため、
**これがそのまま発光シルエットになる**。機体を再描画する別経路が不要で、
「破片は自分が何かを知らない」という責務分割も保たれる。

ホールドフレーム数は機体定義の値。決定事項4の「機体ごとの使い分け」はこの数値のみで表現される。

### 局面2 — 飛散

```
初速 = 機体の速度（慣性の継承）
     + 機体中心からパーツ中心への方向 × 爆発力 / weight
     + 微小なランダム散らし

毎tick: vy    += DEBRIS_GRAVITY
        vx    *= DEBRIS_DRAG
        angle += angularVelocity
```

角速度は初速の横成分に比例させる。勢いよく横へ飛んだ破片ほど速く回るため、慣性が視覚的に一貫する。

### 局面3 — 消滅

寿命の経過に応じて `scale` を 1 → 0 へ縮小する。線形だと最後まではっきり見えたまま急に消えるため、
縮小は後半に効きを強めるカーブとし、最後の 25% で alpha もフェードさせる。
地形は無視して落下し続け、寿命が尽きた時点で `alive = false` とする。

### 描画

`ctx.translate(x, y)` → `ctx.rotate(angle)` → `ctx.scale(s, s)` → `fillRect` の1回。
パーツ矩形は中心原点に正規化して保持する。画面外の破片は描画をスキップする。

## 機体ごとのパーツ構成

既存 `draw()` の矩形を意味単位に束ねたもの。

| 機体 | パーツ | 可動部 | ホールド |
|---|---|---|---|
| Player | 頭部＋バイザー / 胴体 / バックパック / スラスター / 脚×2 / 武装（バズーカ or MG） | 脚、武装 | 5f |
| Carrier | 下部船体（左右2片に分割） / 上部船体（赤） / 発着デッキ / コックピット窓 / エンジンポッド×2 | なし | 6f |
| EnemyDrone | コア / 主翼×2 / 前後ポッド×2 / アイ / 機銃 | なし | 0f |
| EnemyTank | 車体 / 車体上面 / 砲塔 / 砲身 / ホバースカート | 砲身 | 2f |
| EnemyTurret | 基部 / アーム / 旋回体 / 砲身 / 警告灯 | 旋回体・砲身（`currentAngle` を焼き込み） | 2f |
| EnemyAttacker | 頭部 / 胴体 / 肩装甲 / 脚×2〜4（機種別） / 主砲 | 脚（`_drawJointedLeg` の関節座標）、主砲 | 4f |

補足:

- **EnemyTurret** は地形に固定された砲台なので、基部とアームの初速をほぼゼロにする。
  地形すり抜けでも「据え付けられていたものが崩れた」印象になる。
- **EnemyAttacker** は `ENEMY_ATTACKER_TYPES` により脚の本数と形が異なるため、
  脚パーツは静的テーブルを持たず、完全に `getDebrisParts()` 側で生成する。
- パーツ数は1機あたり 6〜14。現在の爆発パーティクルが1機あたり 15〜80 個なので、増分は1〜2割程度。

## 既存の爆発演出との調整

`createExplosion` は現在 20% の確率で灰色のデブリ粒子を混ぜている（`Particle.js:151`）。
本物の破片が飛ぶようになるとこれは冗長で画面を濁らせるため、破片を出す6機体については
爆発側のパーティクル数を控えめにする。爆発が破片を隠しては本末転倒であり、
具体的な数値は実機を見ながら調整する。

破片の同時存在数には上限を設け、超過分は古いものから消す。

## 既知の挙動

Player は死亡した次の tick で即座に母艦へ復帰する（`main.js:618`）。
したがって破片が飛んでいる間、自機は既に母艦上にいる。これは現在の爆発パーティクルでも同じ挙動であり、
本仕様では変更しない。

## テスト方針

`node --test` はヘッドレスであり描画自体は検証できない。既存テスト群と同様、検証可能な不変条件に絞る。

- 全6機体のパーツ定義が空でない配列を返し、各パーツの中心が機体のバウンディングボックスを
  幅・高さそれぞれの1倍以上はみ出さないこと（脚や砲身が機体枠外へ伸びる分の許容を含む）
- `facingRight = false` のときパーツX座標が正しく反転すること
- 物理: 重力で `vy` が単調増加する / 機体速度が初速に継承される / ホールド中は移動しない /
  寿命終了で `alive = false` になる / `scale` が単調減少する
- `spawnDebris` が `game.particles` に想定個数を追加し、同時存在数の上限を超えないこと
- 既存の `explosion-knockback.test.js` が引き続き通ること（破片はノックバックに関与しない）

見た目の良し悪しは実機確認でのみ判断する。実機確認はユーザーが行う。

## 実装順

各段階で動作するものが残る形で進める。

1. `DebrisPart` ＋ 定数 ＋ 物理テスト（単体で完結）
2. `buildDebris` ＋ `game.spawnDebris` ＋ **EnemyDrone**（可動部なし）で1機体を貫通させる
   — **ここで最初の実機確認を行い、方向性の可否を判断する**
3. **Player**（可動脚＋武装）— 可動部フックの雛形を確立
4. **EnemyTank / EnemyTurret** — 単純な可動部
5. **EnemyAttacker** — 最も複雑な脚
6. **Carrier** — 大型機の演出調整
7. 爆発パーティクル側の数値調整と全体の詰め
