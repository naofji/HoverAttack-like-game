# 途中セーブと面セレクト 設計

2026-08-16

## 何を作るか

独立した2つの機能を1つのサブシステムに載せる。どちらも「週が変われば消える進捗」で
寿命が一致するため、保存先を分けない。

- **途中セーブ（1スロット）** — 面クリア後に選ぶと、次の面の頭を再開地点として保存する。
  **コストは10000点。** ゲームオーバー後、そこから何度でも再開できる。再開回数
  （トライ数）を記録し、週スコアランキングで同点時のペナルティに使う。
- **面セレクト** — 今週すでに到達した面を選んで単独で始める。タイムアタック用。
  記録は**面別ランキングにのみ**残し、週スコアランキングには出さない。

## なぜこの形か

- ステージは `stageSeed(weekSeed, missionsCompleted)` から決定的に生成される
  （`GameStateManager.resetLevel()`）。**面の中身を保存する必要はまったくない。**
  数値をいくつか持てば同じ面が再現する。
- `resetLevel()` は毎面 `new Player()` するので、**通しプレイでも各面はフル状態で始まる。**
  よって面セレクトからの開始条件は通しプレイの各面と元から一致しており、面別
  ランキングに同じ表で並べても不公平にならない。開始条件を揃えるための追加実装は不要。

## データモデル

`localStorage` の 1 キー `hoverattack_progress`。

```js
{
  weekId: "2026-W33",
  save: {                    // 途中セーブ。無ければ null
    mode: "normal",          // 再開時はこのモードに固定する
    missionsCompleted: 3,    // = 次に始まる面は4面
    score: 24500,            // 10000点を引いた後の値
    totalTime: 182400,
    stageResults: [ ... ],   // buildStageResult の配列
    tries: 1                 // このセーブから何回目の挑戦か
  },
  reached: 4                 // 面セレクトの解放。今週到達した最大面（1..7）
}
```

### 決めたことと理由

- **週IDで丸ごと無効化する。** 読み込み時に今週と違えば `{ save: null, reached: 0 }` を
  返す。週が変われば面の中身が変わるので、続きも解放も意味を失う。`HighScoreManager`
  の週ロールオーバーと同じ流儀。ただし**アーカイブはしない**（進捗に残す価値がない）。
- **`stageResults` を丸ごと持つ。** 捨てると、再開後にゲームオーバーしたとき
  `_anyStageWouldRank()` が見る配列からセーブ前の面が欠け、**面別ランキングに出せる
  はずの記録が消える。** 保存量より一貫性を取る。
- **10000点はセーブが成立した瞬間に `game.score` から引き、引いた後の値を保存する。**
  引く前の値を保存すると、セーブし直すたびに得をする穴になる。テストで明示的に縛る。
- **`tries` はセーブデータ側に持つ。** 新規セーブで 1。コンティニューするたび `+1`
  して**即座に保存し直す**（保存前に落ちても回数が残る）。別の面でセーブし直したら
  1 に戻る — その面への挑戦回数だから。
- **`reached` は既存の `hoverattack_max_stage_reached` とは別に持つ。** 既存キーは
  週非依存で、面別ランキング表示画面の出現ゲート（`main.js:379`
  `maxStageReached() >= 1`）に使われている。週別に置き換えると**週明けにその画面が
  出なくなる**。既存キーはそのまま残し、面セレクト用の週別カウンタを新設する。
- 壊れた JSON・未知の形・`localStorage` が使えない環境では**セーブ無しとして扱い、
  例外を投げない**（`utils/settings.js` と同じ方針）。

## 構成

| 置き場 | 役割 |
|---|---|
| `src/js/utils/saveData.js` | 純ロジック。`loadProgress(storage)` / `saveProgress(...)` / `canSave(score)` / トライ数の遷移。`storage` を引数で受けるので `node --test` から直接叩ける |
| `src/js/systems/SaveManager.js` | `Game` との橋渡し。セーブの成立（コスト減算＋保存）、復元（`Game` へ流し込んでから `resetLevel`）、`reached` の更新 |
| `src/js/main.js` | 画面遷移とキー処理。新しい `gameState: 'stage_select'` |
| `gas/Code.gs` | `Scores` シートの `tries` 列と `topNForWeek()` のタイブレーク |

`GameStateManager` には足さない。今の120行の見通しの良さが値打ちで、永続化・週判定・
スコア減算を混ぜると失う。`utils/settings.js` にも相乗りさせない — 設定は週をまたいで
永続、セーブは週で消える。**寿命の違う2つを1キーに入れると週リセットで設定まで飛ぶ。**

## 画面と操作

### 面クリア（`mission_clear`）

現状は「任意のキー／クリックで次の面へ」（`main.js:802`）。ここに Yes/No を挟むと
**連打で誤ってセーブして10000点失う**。確認はキーの割り当てで表す。

```
    STAGE 3 CLEAR
    [W] NEXT STAGE          ← 従来どおり、任意キー／クリックでも進む
    [S] SAVE & NEXT          -10000 PTS
```

`S` を押したときだけセーブ。スコアが10000未満なら3行目を暗く落として `SCORE TOO LOW`
を添え、`S` は無反応。タイムボーナスの加算アニメ（`_updateTimeBonusSlot`）が走っている
間は従来どおり入力を受けないので、**加算後の確定スコアで判定できる。**

### ゲームオーバー（`gameover`）

現状は4秒後に自動で `_tryGoToRanking()`（`main.js:791`）。セーブがあるときだけ、
その前にカウントダウン付きの選択を挟む。放置すれば従来どおりランキング登録へ流れる
（既存の自動遷移の性格を保つ）。

```
    GAME OVER
    CONTINUE FROM STAGE 4?   [C] YES     TRY 2
    ... 9
```

`C` を押したら `tries` を +1 して保存し直し、セーブ地点から再開する。
**ランキング登録には行かない**（ランがまだ終わっていない）。

カウントダウンは **9秒**から始める（現行の自動遷移が4秒。選択肢を読んで決める時間として
倍以上を取る）。実機で長すぎ・短すぎを見てもらう。

### タイトル

`A`/`D`（モード切替）と同じ流儀で下部に小さく提示する。**どの面から再開するのかと
モードを必ず併記する** — タイトルで `A`/`D` を触った後、再開時にモードが保存値へ
固定されることとの食い違いを防ぐため。

```
    [C] CONTINUE - STAGE 4 / NEWTYPE  (TRY 2)     ← セーブがあるときだけ
    [S] STAGE SELECT                              ← reached >= 1 のときだけ
```

行が出ていない＝使えない、が一目で分かる。

**タイトルの `C` もゲームオーバーの `C` と同じく `tries` を +1 する。** どちらも
「セーブ地点からの再挑戦」で、経路で回数が変わってはならない。

**セーブがある状態で通常スタート（任意キー）してもセーブは消えない。** 新しいランを
1面から始めるだけで、次にセーブが成立するまで元のセーブが残る。誤って任意キーを
押しても続きを失わないため。

### 面セレクト（新規 `gameState: 'stage_select'`）

`A`/`D`（タイトルのモード切替と同じキー）で 1..`reached` を選び、`W` またはクリックで
開始する。`Escape` でタイトルへ戻る。**面クリア画面が `W` で次へ進むのと同じ割り当てに
揃える**（新しい決定キーを増やさない）。モードはタイトルの選択を引き継ぐ。**週スコアランキングには出さない**ので、記録が面別ランキングにのみ残る旨を
1行出す。

## スコアとランキング

### 週スコアランキング（オンライン＋ローカル）

- **`tries` を追加し、同点時のタイブレークにのみ使う。** スコアそのものは減点しない
  — 10000点のコストが既に実質的なペナルティで、二重取りにしない。
  並びは `score 降順 → tries 昇順 → 登録時刻 昇順`。
- **表示は `tries >= 2` のときだけ** 名前の後ろに `T2` のような小さな印。1 のときは
  何も出さない（セーブを使わない大多数の行を汚さない）。
- **オンライン**は `gas/Code.gs` の `Scores` シートに `tries` 列を足し、
  `topNForWeek()` の比較に第2キーを入れる。古い行は `tries` が空になるので
  `Number(x) || 1` で 1 とみなす。
  **⚠️ 列の追加はスプレッドシートの手作業。** その後 `clasp push` →
  `clasp create-deployment -i <デプロイID>`（`-i` を忘れると新しい URL が発行される）。
  手順は `docs/superpowers/specs/2026-07-15-gas-setup.md` の 3b 節。

### 面別ランキング

`tries` は持たせない。面セレクトからの記録は常に単独プレイで、常に 1 になり意味が薄い。
既存の `stageResults` → `submitStages()` の経路をそのまま使う。

### 面セレクトのラン終了時

`_tryGoToRanking()` の判定から週ハイスコアの条件を外し、`_anyStageWouldRank()` だけで
名前入力に進む。面別トップ5に入ったときだけ名前を聞かれ、週スコアには送られない。

## テスト方針

`utils/saveData.js` は偽ストレージを渡して直接叩く。

- `loadProgress()` — 週IDが違えば既定値／壊れた JSON・未知の形・`localStorage` 例外でも
  既定値を返し、投げない
- `canSave(score)` の境界 — 9999 は不可、10000 はちょうど可
- **保存される `score` が10000を引いた後の値であること**（引く前の値が保存されて
  いないことを明示的に見る）
- `tries` の遷移 — 新規セーブで 1、コンティニューごとに +1、別の面でセーブし直すと 1

ランキングの並びは `tests/HighScoreManager.test.js` と `tests/gas-core.test.js` に
同点ケースを追加（`tries` 1 と 3 で 1 が上／`tries` 欠損の旧データは 1 扱い）。

画面遷移は `Game` のメソッドを直接呼ぶ既存の形（`tests/base-emergency-defense-full-chain.test.js`
が原型）で:

- 面クリアで `S` → スコアが 10000 減り、保存が1回走り、次の面へ進む
- 10000未満で `S` → **何も起きない**（保存が呼ばれない・スコアが動かない）
- セーブ有りのゲームオーバーで `C` → `tries` が +1 で保存され、`ranking_entry` へ行かない
- 放置してカウントダウン満了 → 従来どおり `_tryGoToRanking()` へ
- 面セレクトから始めたランの終了 → 週ハイスコア判定を通らず、面別だけで名前入力が決まる

**ソース文字列を grep するテストは書かない**（CLAUDE.md の規約。過去2回誤検知あり）。
呼び出し回数と状態で見る。

## 実機で確認してもらう点

- 面クリア画面の3行が枠に収まるか（既存の警告バナーで `measureText` による自動縮小を
  入れた前例あり）
- ゲームオーバーのカウントダウンの長さ
- 面セレクトの操作感
- ハードリロード（Cmd+Shift+R）が要る

## やらないこと

- **ミッション途中のスナップショット**（敵の位置・HP・破壊された地形・弾）は作らない。
  再開地点は常に面の頭。
- 複数セーブスロット。1つだけ。
- 面別ランキングへの `tries` 反映。
- キー割り当ての変更機能（既存の「表示のみ」のまま）。

## 補足

`HighScoreManager` の `MIN_SCORE` が偶然 10000（ランキング登録の下限）。セーブコストと
同額だが**別の定数**で、連動させない。両方 `Constants.js` に置き、セーブ側は
`SAVE_COST` として独立させる。
