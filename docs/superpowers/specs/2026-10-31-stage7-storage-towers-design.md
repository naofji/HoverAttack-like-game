# 7面: お宝を格納塔に入れる

2026-10-31。親: `2026-09-06-stage7-fortress-design.md`、`2026-10-31-stage7-extra-life-design.md`。

## 何のためか

要塞のお宝（オーバードライブ・リペア・残機）は、今は最下階の右端の室の床に**むき出しで**並んでいる。
着いた時点で中身が全部見えてしまう。

実機を見たユーザーの提案: 要塞の奥に**格納塔が3本林立**していて、「何かがあるのは分かるが、中身は分からない」。
壊して初めて中身が出る。

## 決めたこと（ユーザーの判断）

| 論点 | 決定 |
|---|---|
| 見た目 | 縦型のタンク。**自機と同じくらいの大きさ** |
| 硬さ | **ミサイル1発ほど**で壊れる |
| 壊せる武器 | ミサイル・**機関砲・グレネード**のどれでもよい |
| 壊したとき | 敵の撃破ドロップと同じ形で、**今のお宝をそのまま落とす**（中身の決め方・配置は今のまま） |
| 中身の手がかり | 出さない。3本とも同じ見た目 |
| 形と色 | **黄白色っぽい円筒形のタンクが足台の上に載った形**。少し目立つように、**オレンジ色の横縞の光が明滅**する |
| 汎用性 | 今は7面の要塞の奥だけ。ただし**各ステージにも1か所置くことを検討中**なので、要塞に縛られない汎用の作りにする |

## 作り

### 0. 汎用にするための形

格納塔は「どこに立つか」と「中身は何か」だけを受け取る部品にし、要塞のことは知らない。

- **置き場所の一覧は Map が持つ**（例: `map.storageTowerSpawns`、要素は `{x, y, kind}`。`y` は塔の下端＝床の上面）。
  7面では要塞の生成がここに足す。将来ほかの面に置くときは、その面の生成が同じ一覧に足すだけで、
  塔の本体・当たり判定・描画・湧かせ方には手を入れない
- **中身の種類からアイテムを作る表を1つにする**（`kind` → アイテムのクラスと入れる配列）。
  今の `SpawnManager.spawnTreasures()` の if の連なりをこの表に置き換え、格納塔の破壊もこの表を通す。
  新しい中身を足すときは表に1行
- 湧かせ方は `SpawnManager` に1つ（例: `spawnStorageTowers()`）。面の種類で分岐しない（一覧が空なら何もしない）
- 寸法・HP・色・明滅の周期は `Constants.js` の `STORAGE_TOWER_*` に置く

### 1. 置き場所（今回は7面の要塞だけ）

- 今のお宝の位置（`planZoneContents` の `treasures`、`assignExtraLives` で残機に替わったものも含む）に、
  **お宝の代わりに格納塔を1本ずつ立てる**。中身はその `kind`
- 地形・お宝の決め方・個数（`FORTRESS_TREASURE_COUNT=3`）は変えない。乱数も使わない（週次の決定性はそのまま）
- 床の上に立てる（塔の下端＝お宝を置いていた床の上面）
- ほかの面への配置（どこに・中身は何か）は**今回は作らない**。決まったら別の設計にする

### 2. 格納塔

- 大きさ: 幅 16px・高さ 24px（自機 `PLAYER_WIDTH`×`PLAYER_HEIGHT` と同じ）。定数にする
- HP: 15（`DAMAGE_PLAYER_MISSILE` 1発）。機関砲（3）なら5発、グレネード（80）なら1発
- **敵の一種にはしない。** 撃破数・スコア・Auto Aim の対象に入れない。`FortressBarrier` と同じく
  専用の配列（例: `game.storageTowers`）に置き、自分で当たり判定を回す（`FortressBarrier` の作りを手本にする）
- 被弾したら HP バーを出す（`_drawHpBarIfDamaged`。バリアのユニットと同じ）
- 壊れたら小さな爆発（`playBlast` など既存の演出）を出し、塔の位置からお宝を1個落とす。
  落ちたお宝は今のアイテムと同じ配列に入り、落下・接地・拾得はそのまま動く

### 3. 描画

- **黄白色っぽい円筒形のタンクが足台の上に載った形。** 全体の高さ 24px のうち、下の数 px を足台
  （暗い金属の脚と横板）、その上を円筒にする。円筒は左右の端を暗く・中央寄りを明るくして丸みを出し、上に浅いふた
- **オレンジ色の横縞の光が明滅する。** 円筒に横縞を数本入れ、周期的に明るさを上下させる（光り始めと消え際がなめらか）。
  周期・色・縞の本数は定数。明滅は描画だけで、ゲームの状態や乱数には影響させない
  （位相は塔ごとにずらすと林立して見える。ずらし方は位置から決め、乱数は使わない）
- 3本とも同じ絵。中身の色やアイコンは出さない
- ほかの面の背景（雪・水・霧など）の上でも目立つ色にするため、色は面ごとに変えない

### 4. 寿命

- お宝と同じ。面の開始（`GameStateManager` の面のリセット）で作り直す。今は7面以外では一覧が空なので塔は無い

## 私の判断（未承認）

1. **自機は塔を通り抜けられる**（障害物にしない）。地雷と同じ扱い。壁にすると最下階の右端の室が狭くなり、
   今の守備隊・通り道の調整をやり直すことになるため
2. **敵の弾・爆発では壊れない**（自機の武器だけ）。守備隊の流れ弾で勝手に開くと「壊して中身を見る」が崩れるため。
   地雷の誘爆でも壊れない
3. HP 15（ミサイルちょうど1発）
4. 3本の間隔は今のお宝と同じ2タイルおき（塔の間に 16px のすき間）。詰まって見えたら実機で広げる
5. 被弾・破壊の音は既存の金属の被弾音と小さな爆発音を使い、新しい音は作らない
6. 横縞の明滅は塔ごとに位相をずらす（3本が同時に点滅するより林立して見えるため）。ずらし方は位置から決める
7. 塔の色は面ごとに変えない（ほかの面に置いたときも目立つように）
8. ほかの面への配置は今回は作らず、置き場所の一覧（`storageTowerSpawns`）に足せば立つ形までにとどめる

## 作らないもの

- 中身の配置や確率の変更、新しいアイテム
- 塔の誘爆・連鎖
- 要塞の外の格納塔

## テストで縛ること

- 7面の要塞のお宝の位置ごとに塔が1本ずつでき、むき出しのお宝は無い
- 塔の中身の数と種類が、今のお宝（オーバードライブ・リペア・残機）と一致する
- ミサイル1発・機関砲5発（4発では壊れない）・グレネード1発で壊れ、そのとき中身が1個だけ落ちる
- 敵の弾では壊れない。壊れた塔は2度目のドロップをしない
- 撃破数・スコア・Auto Aim の対象に入らない
- 7面以外では塔が無い。週次の決定性（`MapDeterminism`）は変わらない
- 汎用性: 偽の地図の `storageTowerSpawns` に好きな位置と中身を入れれば、7面でなくても塔が立ち、壊すとその中身が出る
- 中身の表: どの `kind` も正しいアイテムの配列に入る（お宝の湧きと格納塔の破壊の両方）
- 明滅: 時間で横縞の明るさが変わり、塔ごとに位相がずれる（偽 ctx で色を記録して確かめる）

## 実機で見るところ

| 見るところ | 調整用の定数 |
|---|---|
| 「何かある」と分かるか、塔らしく見えるか | 塔の大きさ・色（`STORAGE_TOWER_*`） |
| オレンジの横縞の明滅が目立ちすぎないか・目立たなすぎないか | 明滅の周期・明るさの幅・縞の本数 |
| 3本の並びが詰まって見えないか | お宝の間隔（`planZoneContents`） |
| 壊す手応え（ミサイル1発・機関砲5発） | 塔の HP |
| 中身が出たと分かるか（落ちる・光る） | — |
