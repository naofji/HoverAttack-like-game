# ドッキング補給のSE（回復ハム・装填クリック・Readyボイス）

## 目的

ドッキング中の補給は、いま画面のゲージが動くだけで音がない。母艦のエンジン音が
鳴っているだけなので、「補給が進んでいる」「もう出撃できる」が音で分からない。
補給の進行と完了を耳で追えるようにする。

補給は段階式で、実時間で HP 3.6秒 / ミサイル・グレネード 6秒 / 燃料 4秒かけて満ちる
（`Player._updateDockedResupply()`）。この進行そのものを音にする。

## 鳴らす3つの音

| 音 | 何に反応するか | 形 |
|---|---|---|
| 回復ハム | HP が満タンになるまでの間ずっと | 連続ループ。進捗で音程が上がる |
| 装填クリック | ミサイル／グレネードが1発入るたび | 短い金属の打撃。弾種で音色が違う |
| Ready ボイス | 全リソースが満タンになった瞬間に1回 | 合成音声「レディ」 |

装填クリックは1発＝1クリックで厳密に対応させる。補給速度からミサイル4回/秒・
グレネード2回/秒（計6回/秒）鳴るが、残弾が耳で追えることを優先し、音量を抑えて
成立させる。間引いて発数との対応を崩すことはしない。

Ready は「HP・ミサイル・グレネード・燃料が**全て**満タンになった瞬間」の1回だけ。
リソースごとに鳴らすと短時間に音声が重なって煩い。

## 既存の共通合成に乗せる

`src/js/audio/weaponSounds.js` に、プロファイルの表（`WEAPON_SOUNDS`）と組み立て
1本（`renderWeaponSound()`）というデータ駆動の合成がある。部品は `hiss` / `tone` /
`puffs` / `clicks` の4つで、発射音だけでなくリロードの「ガチャリ」もここにある。
機構の音は既にこの表の担当なので、新しい音は原則ここに足す。

AudioManager 側の `playDock()` / `playLanding()` などは手書きのノードグラフだが、
今回はそこに手書きを増やさない。

### 装填クリック — 合成コードの追加ゼロ

`clicks` パーツがそのまま金属の打撃なので、表に2行足すだけで済む。

- `ammoMissile` — `count: 1`、高め・短く軽い「カチッ」
- `ammoGrenade` — `count: 1`、低め・やや長い「コツン」

`metal`（非整数倍の共鳴比）は既存 `reload` と揃え、同じ機構が動いている音に聞こえる
ようにする。`clicks` は中心周波数が低いほど通る帯域が狭く痩せるので、`ammoGrenade`
のゲインは実測して聞こえる強さを `ammoMissile` に揃える。

鳴らす口も既存の `audioManager.playWeapon(kind, x, y)` をそのまま使う。新しい
公開メソッドは追加しない。自機は母艦の上にいてカメラの中心付近なので、位置による
減衰は問題にならない。

### Ready ボイス — 部品を1つ足す

現在の `tone` は単一オシレータの掃引で、母音のフォルマントが作れず声にならない。
`renderWeaponSound()` に5つ目の部品 `voice` を実装する。

- 音源は声帯パルス（ノコギリ波）。f0 は約 150Hz でほぼ固定にしてロボットらしくする
- それを3本のバンドパス（F1/F2/F3）に通す
- プロファイルの `segments` に沿って母音を **e → i** へ遷移させ「レディ」にする
- d の子音は一瞬のゲート断で表す
- 全体で 0.35秒程度

音の中身（フォルマント周波数と時間配分）はプロファイル表側に書く。「音の違いは表だけに
現れ、合成の手順は1つ」という既存の方針を保つ。

### 回復ハム — ループ音側の共通化が必要

`weaponSounds.js` は開始時刻を決めて鳴らし切るワンショット専用で、鳴り続けながら
パラメータが動く音には使えない。ループ音は AudioManager 内に hover / enemyHover /
carrierEngine の3つあり、どれも

1. ノードが無ければ作る
2. `setTargetAtTime` で目標値に追従させる
3. 止めるときはフェードして 250ms 後に `stop()` する

という同じ骨格を書いている。素で4つ目を足すと4回目の重複になるので、ヘルパー
`_loopSound(key, { build, tune })` を1本作り、この骨格を集約する。

載せ替えるのは**回復ハムと carrierEngine の2つ**に限る。hover / enemyHover は音量を
実測して調整済みで、触ると質感が変わるリスクに見合わない。carrierEngine は今回の
ドッキング周りで一緒に鳴る音なので、載せ替えても実機での確認がドック1回で済む。
載せ替えに際して音のパラメータ（周波数・ゲイン・時定数）は現状値のまま変えない。

回復ハムの音作りは、母艦エンジンの低域と帯域が被らないよう中域に置く。三角波の
穏やかなハムで、進捗に応じて音程を約 300Hz → 460Hz へ上げる。あと何秒で満ちるかが
音程で分かる。

## 発火の判断は Player 側に置く

`Player._updateDockedResupply()` は各リソースの加算をしている唯一の場所で、増加の
前後を比較できる。判断はここに置く。

- 加算前後で `Math.floor(missiles)` / `Math.floor(grenades)` が上がったフレームに
  対応するクリックを鳴らす
- HP が満タン未満の間は毎フレーム `startRepairHum(hp / PLAYER_MAX_HP)` を呼ぶ
  （毎フレーム呼んでよいループ、という既存 `startCarrierEngine` と同じ約束）。
  満タンに達したフレームで `stopRepairHum()`
- 全リソースが満タンになった瞬間に Ready を1回。`_dockAllFull` フラグで多重発火を
  防ぎ、`resupply()`（ドック成立時に呼ばれる）で false に戻す

**ドックした時点で既に全部満タンなら Ready は鳴らさない。**「未満 → 満タン」の変化を
見るのであって、満タンであること自体では鳴らさない。

離脱の後始末は `main.js` の undock 分岐に置く。既に `stopCarrierEngine()` を呼んで
いる場所に `stopRepairHum()` を足す。回復途中で離陸してもハムが残らない。

## テスト

- `tests/dock-resupply-sound.test.js`（新規／既存の `spyAudio` パターンを流用）
  - ミサイルのクリックがちょうど24回、グレネードがちょうど12回
  - HP が満タンになったフレームで `stopRepairHum` が呼ばれる
  - Ready がちょうど1回
  - 最初から全部満タンなら Ready が0回
  - 補給途中でアンドックするとハムが止まる
- `tests/weapon-sounds.test.js` に `voice` パーツを追加。出力が NaN にならず、無音でもない
- `tests/audio-manager.test.js` にループヘルパー
  - `start` を二重に呼んでもノードは1組しか作られない
  - `stop` の二重呼び出しで例外が出ない
  - 載せ替え後の carrierEngine が従来と同じパラメータを設定する
- `tools/render-dock-sounds.mjs`（新規）で3音をオフラインレンダリングし、A特性で
  既存SE（`playPickup` / `reload`）と音量を比較する。音作りを変えたら実測する、という
  この repo の決まりに従う

## 調整を前提にすること

音色の具体値（ハムの音程レンジ、Ready の声の高さと速さ、クリックの音量バランス）は
実装後に実機で聞いて詰める。実機確認はユーザーが行う。
