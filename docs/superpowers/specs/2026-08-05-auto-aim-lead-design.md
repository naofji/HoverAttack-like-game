# Auto Aim の偏差射撃（Aim Lead）

日付: 2026-08-05

## 目的

Auto Aim 中、動いている敵に弾が当たらない。自機の武器はミサイル（速度6）もマシンガン（速度4）も
**直進弾で誘導が無い**のに、`autoAimTarget` が敵の**現在位置**をそのまま指しているため、
弾が届くころには敵がそこにいない。

「弾が届くころに敵がいる場所」を狙わせて、Auto Aim の利便性を実際の命中に結びつける。

## 決定事項

1. **照準は敵に据えたまま、着弾予定地点は別マーカーで示す**（戦闘機の HUD 風）。

   当初は `autoAimTarget` ごと予測地点へずらして照準を動かしたが、実機で照準が敵から外れて
   フラフラと浮き、狙っている敵を見失って目障りだった。照準（ターゲットボックス）は
   ロックした敵の中心に固定し、そこから予測地点へ**破線**を引いて先端に**リードサークル**を描く。
   直進弾はそのリードサークルへ向けて発射する。

   そのため状態を2つに分ける。

   - `autoAimTarget` — ロック中の敵の中心。照準の描画に使う
   - `autoAimLeadPoint` — 着弾予定地点。リードマーカーの描画と、直進弾の発射角に使う
2. **偏差の強さは 75%**（`AUTO_AIM_LEAD_STRENGTH = 0.75`）。
   当初 1.0（完全に合わせる）で実装したが、照準ごと動かす方式では追従が効きすぎて 0.25 まで下げた。
   照準を敵に固定してリードマーカーで示す方式に変えたあと、見た目が落ち着いたので 0.75 へ戻した。

## 設計

### 敵の速度をどう得るか

敵は種類ごとに移動の実装が違う。`vx` を積む型、座標を直接動かす型、そもそも動かない砲台があり、
`vx` を持つとは限らない。そこで **描画される中心座標が 1 tick で動いた量**を測る。
どの敵にも一様に効き、敵側のコードに手を入れずに済む。

測るのは**窓のあいだの平均速度**（最新と最古の差 ÷ 区間数）。

**実機で見つかった不具合（2026-08-05）:** 地上の戦車で照準が激しく上下に振動した。
原因は、着地スナップの都合で戦車の中心Yが **3 tick 周期で +0.3 / +0.6 / −0.9** と揺れていること。
正味の移動はゼロなのに、1 tick の差分では最大 0.9px 動いて見え、それが飛行時間（最大60tick）で
増幅されていた。指数平滑ではこの往復を打ち消せない。

対策は2つ。

- **窓の区間数を振動周期の倍数にする**（`AUTO_AIM_LEAD_WINDOW = 13` → 区間12、3の倍数）。
  往復がちょうど打ち消し合い、実測で誤差ゼロになる。
- **デッドゾーン**（`AUTO_AIM_LEAD_DEADZONE = 0.15`）で残った微小な値をゼロへ落とす。
  戦車の実際の水平移動は実測 0.41px/tick なので、本物の動きは消えない。

窓が埋まるまでは速度を報告しない。区間数が半端だと往復が打ち消し合わず、
ロック直後だけ照準が飛ぶ。埋まるまでの12 tick（0.2秒）は偏差ゼロで待つ。

ロック対象が別の敵に変わったら履歴を捨てて測り直す。前の敵の速度を引き継ぐと、
乗り換えた瞬間に的外れな方向へ照準が飛ぶ。

### 着弾予定地点の求め方

弾の飛行時間と、その時間ぶん敵が進む距離は互いに依存する。反復して収束させる
（等速直線運動の仮定なら `AUTO_AIM_LEAD_ITERATIONS = 3` 回で十分）。

```
t = 0
3回繰り返す:
    p = 敵の位置 + 敵の速度 × t × strength
    t = min(|p - 射手| / 弾速, AUTO_AIM_LEAD_MAX_TICKS)
着弾予定地点 = 敵の位置 + 敵の速度 × t × strength
```

`AUTO_AIM_LEAD_MAX_TICKS = 60`（1秒ぶん）で頭打ちにする。上限が無いと、遠くの高速な敵に対して
予測が暴走し、照準が画面外の見当違いな場所へ飛ぶ。

弾速は**装備中の武器**のものを使う。ミサイル（6）とマシンガンで（4）偏差量が変わる。

### 配置

`src/js/utils/aimLead.js` に置く。`main.js` は DOM に依存していてテストから import できないため、
計算とトラッキングを独立モジュールに閉じ込める。

- `predictLeadPoint(opts)` — 着弾予定地点を返す純関数
- `AimLeadTracker` — 中心座標の差分から敵の速度を測る（平滑化と対象切り替えの管理）

`main.js` 側は `_leadPointFor(enemy)` を追加し、`autoAimTarget` を組み立てていた2箇所
（ロック継続時・新規ロック時）をこれに置き換える。ロックが外れる経路では `aimLead.reset()` を呼ぶ。

### リードマーカーの表示

- ずれが `LEAD_MARKER_MIN_OFFSET`（4px）未満なら描かない。止まっている敵では照準に重なるだけで、
  わずかな揺れでちらついて目障りになる
- 破線を引いたあとは必ず `setLineDash([])` で解除する。解除しないと後続の描画まで破線になる

## グレネードの扱い

グレネードは重力を受ける放物線で飛行時間も長いため、直進弾の弾速で求めた偏差を当てても正しくない。
グレネードと軌道プレビューは `autoAimTarget`（＝照準が指している敵の中心）を狙う。
プレイヤーには照準の位置がそのまま投擲先として見えるので、見た目とも一致する。

## テスト方針

`predictLeadPoint` と `AimLeadTracker` はどちらも純粋なので直接テストできる。

- 止まっている敵には偏差を取らない
- 横切る敵には進行方向へ偏差を取る
- 収束したリード点で「弾の飛行時間」と「敵の到達時間」が一致する（予測が正しいことの本質的な検証）
- 遅い弾ほど、遠い敵ほど偏差が大きい
- 上限で頭打ちになる
- `strength` で弱められる / 0 なら現在位置そのもの
- 弾速 0 でゼロ除算しない
- トラッカー: 初回は速度ゼロ / 差分から速度を得る / 平滑化が効く / 対象切り替えでリセット / `reset()`

`main.js` の配線は import できないため、上記の契約テストで担保する。
