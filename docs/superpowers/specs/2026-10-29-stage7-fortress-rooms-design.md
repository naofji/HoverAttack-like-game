# 7面の要塞 段C の土台 — 室 → 廊下 → 室

2026-10-29。親は `2026-09-06-stage7-fortress-design.md`（§7 の「室（廊下の交点）に砲台とダメージ床」）。
ユーザーの問い: 「『室＝廊下の交点〜交通の要衝』という形が実現できるようにマップの作り方を工夫することはできますか？」→ 提案を承認（「そのまま進めて」）。

## なぜ作り直すか

設計書の元案は「廊下の格子の交点が室」だったが、**縦横の格子は真上から見た間取り図に見える**（実機の指摘）ので、階層構造に作り直してあった。
そのとき「交点」と「通路」の区別が消え、階はただの長い空間になっていた。段Cの仕掛け（隔壁扉・ダメージ床・砲台の巣）の置き場所が決まらない。
階層構造の中に断面として「交点」と「通路」を作る。

## 決めたこと（提案をユーザーが承認。数値は私の判断）

- **室** ＝ 縦穴（シャフト・上の入り口）の着地点と出発点、左の入り口、お宝の奥。幅は縦穴の左右に `FORTRESS_ROOM_MARGIN`(2)、入り口とお宝の室は `FORTRESS_ROOM_W`(8)。天井高のまま
- **廊下** ＝ 室と室のあいだ。天井に金属の梁を足して高さ `FORTRESS_CORRIDOR_H`(4)（3 は「若干窮屈」と言われた）。幅 `FORTRESS_CORRIDOR_MIN_W`(4) 未満の隙間・端の尾は室に併合する（切り欠きに見える）
- 天井高 5→6（室6・廊下4で差を2行に）。階のピッチが 7 になり区画の高さ 18〜25 では2階が大半になったので、区画の高さを 24〜31 に（3〜4階）
- シャフトの左右は**最下階から数えて**割り当てる: 最下階への着地を必ず左にして、右奥のお宝までを廊下にする
- バリアは「室と室のあいだ」の廊下（`between`）の中央に、階ごとに最大1本（以前は階ごとに必ず1本・廊下の無い階は立たない）。上のユニットは梁の下
- 守備隊は室に置く。天井の砲台は上に縦穴の無い列、床の砲台と戦車は下に縦穴の無い列だけ
- `zone.rooms` / `zone.corridors`（`between`: 室に挟まれた通路か、行き止まりの尾か）を返す。**段Cの置き場所**: 隔壁扉＝廊下の室との境目、ダメージ床＝廊下の床、砲台の巣＝室

## 見つけた潜在バグ（既存。この変更で直した）

入り口の守衛（左の入り口の天井付け・床置きのタレット）が、20区画のうち6区画で宙に浮いていた。
上の縦穴（天井が無い）が守衛の真上に来る、1つ目のシャフト（床が無い）が足元に来る、の2通り。上の縦穴と1つ目のシャフトを左端から離して開けるようにした
（`topGateOffset` / `firstShaftOffset` ＝ `guardInset + 2`）。天井の守衛は階の本当の天井に付ける（天井高 > 開口の高さのため）。

## 実測（seed 1〜8、7面）

区画 4個（全シード）／階 3〜4／室 20〜24・室に挟まれた廊下 8〜12／バリア 8〜12（以前は平均 約10.6）／区画の面積 7.0〜8.3%（以前 5.9%）。

## 検証

- `tests/fortress-rooms.test.js`（新設）と `tests/fortress.test.js`（バリアの定義を更新）。18通りの壊し方で全部赤を確認（最初は6つ生き残り、縦穴の室の余白・「あいだ」の判定・最上階の天井砲台のテストを足して殺した）
- 湧き位置の基準線（`terrain-shape-grounded-invariance`）は7面を外した。変更前（c5a9509）のコードで記録した値と変更後が一致（他の面は不変）
- 区画の内側の空洞は1つにつながる（梁を足しても孤立しない）

## 実機で見るところ（Cmd+Shift+R）

| 見るところ | 定数 |
|---|---|
| 室と廊下の差が読めるか。廊下が窮屈でないか | `FORTRESS_CORRIDOR_H` / `FORTRESS_CEILING_H` |
| 室の広さ（縦穴の周り・入り口・お宝） | `FORTRESS_ROOM_MARGIN` / `FORTRESS_ROOM_W` |
| 区画が大きくなった（3〜4階）ことの手応え | `FORTRESS_ZONE_H_MIN` |
| 廊下の中央のバリアで、階の横断が重くないか | （バリアの数は階数と廊下の数で決まる） |
