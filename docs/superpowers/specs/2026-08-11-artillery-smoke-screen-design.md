# artillery の煙幕（スモークスクリーン）設計

2026-08-11

## 何を作るか

artillery 型の敵アタッカーに、**自機に発見された瞬間に煙幕を張って自分の位置を隠す**能力を足す。
煙の中の敵は目視できず、Auto Aim のロック対象からも外れる。弾そのものは通るので、
位置を読めば倒せる。

新しい敵の種類を足すのではない。既存の artillery が持つ「遮蔽を探し直す」挙動に、
その移動を隠す手段を1つ与えるだけ。

## 引き金 — 既存の cover seek に相乗りする

`EnemyAttacker._updateCoverSeek()`（`src/js/entities/EnemyAttacker.js:502`）は
`ATTACKER_COVER_CHECK_INTERVAL` ごとに自機との LoS を判定し、通っていれば
`inCover = false` にして遮蔽位置を探し直す。**この「露出を検出した瞬間」が
そのまま「ばれた瞬間」**なので、ここに発煙を差し込む。

- 条件: **LoS が通った判定の回すべて**、かつ発煙クールダウンが空いている
- クールダウン: 480 tick（8秒）。回数は無制限
- 対象: `config.usesSmoke` が真の型のみ（型の表に1行足す。今は artillery だけ）

**「隠れていた → 露出した」への状態遷移で絞ってはいけない**（実装時に一度やって
バグにした）。`inCover` はチェック時点では前回の値なので、`if (!this.inCover)` で
絞ると意味が反転する: いちばん撒いてほしい「見つかった瞬間」（前回 in cover →
今回 露出）で撒かず、「露出が続いているだけ」の回で撒く。実際に発見が
`ATTACKER_COVER_CHECK_INTERVAL`（30 tick）遅れ、その間に次の遮蔽へ着いてしまえば
一度も撒かないまま終わっていた。連発の抑制はクールダウンの役目であって、
状態遷移で絞る必要はない。

新しい状態を足さない理由: 煙を張ってから逃げ直す動きは、既存の
`_findCoverX` → `coverGoalX` へ歩く経路がそのまま「煙に隠れての移動」になる。
ステートマシンに手を入れるほどの利得がない。

## 煙のモデル

`game.smokeScreens` に `SmokeScreen`（`src/js/entities/SmokeScreen.js`）を1つ積む。
1つの雲が14個のパフを持ち、**パフが全部消えたら雲も死ぬ**（雲は独自の寿命を持たない。
撒きをずらすので、雲の時計とパフの時計を別に持つと必ずどちらかが先に切れて、
まだ濃いのに消える／消えたのに判定が残るのどちらかが起きる）。

パフは**自分の経過時間ひとつ**から半径・alpha・色の3つが出る。出たては小さく濃く白っぽく、
古くなるにつれ大きく薄く紫がかった灰になり、最後は完全に透明になって消える。

| 項目 | 値 | 根拠 |
|---|---|---|
| パフ数 | 19 | 中心1 ＋ 内側の列9 ＋ 外側の列9。配置表の合計と一致していること |
| 半径 | 44px → 100px（自分の寿命を通じて単調に拡大） | **列の距離（内側21px / 外側42.5px）より大きく取ること。** 小さいと扇形の列がただの点の並びになり、隣と繋がらないので壁にならない |
| パフ最大 alpha | 0.62 | 上限なしで素直に重ねるため、1枚は薄く。扇形の配置にしてから停滞中も判定点の濃さがじわじわ落ちる（列が外へ漂うぶん）ので、0.50 から余裕を持たせた |
| 撒く場所 | **決め打ち**（下の「撒く場所」を参照） | 乱数で散らすと、たまたま片側に寄ったり中心が空いたりして「噴き出した」形に見えない回が出る |
| パフの寿命 | 810 tick | うち721 tick が濃さを保つ停滞。normal モード 0.8x の実時間で **15秒**（newtype 1.0x では12秒）。実測の隠蔽持続 15.5〜15.9秒 |
| 雲の全長 | 822 tick（撒き12 ＋ パフ810） | 最後に撒かれたパフが死ぬまで |
| 発煙の撒き方 | 12 tick に分散 | 一斉に生むと全パフの年齢が揃い、雲が一様に膨らんで一様に薄れる（時間変化が見えない）。ずらすと機体の近くに白い生まれたてが残り、外側に紫灰の古いのが漂う層ができて湧き上がって見える |
| 漂い | 外向きの微小な初速 ＋ ゆっくり上昇 | |
| パフごとの大きさ | ±35% | 位置だけ散らしても、同じ年齢のパフが全部同じ半径では「同じ丸の反復」に見える |
| 回転 | 基準0.6°/frame ±70%。**向きは左右で逆**（右は時計回り、左は反時計回り） | 噴き出した煙が外側へ巻き上がる動きになる。符号を乱数で決めると隣り合うパフが逆向きに回って互いを打ち消して見えた。速さを揃えると機械仕掛けに見えるのでばらつかせる |

### 撒く場所 — 乱数ではなく決め打ちの扇形

中心 → 内側の列 → 外側の列、の順に撒く。乱数で散らすと、たまたま片側に寄ったり
中心が空いたりして「噴き出した」形に見えない回が出る。決め打ちなら、どの発煙でも
同じ品質になる。

扇形は時計の文字盤で **8時（左下）から 12時 を通って 16時＝4時（右下）まで**の240°。
真下の120°を空けているのは、そちらは地面で、煙は上へ回り込むほうが自然なため。

```
       11  12  1
     10    ·    2
     9   (機体)  3
      8         4
         （空き）
```

配置表は `SmokeScreen.js` の `EMISSION_RINGS`（列ごとの枚数と距離）で、起動時に
`SMOKE_EMISSION_SLOTS`（`{angle, dist}` の並び）へ展開する。**合計は
`SMOKE_PUFF_COUNT` と一致していること**（テストで縛っている）。

守るべき関係が2つある。

- **パフの半径は列の距離より大きく取る。** 内側21px / 外側42.5px に対して半径は
  44px から。小さいと列がただの点の並びになり、隣と繋がらないので壁にならない
- **中心のパフは動かさず、縮ませない。** 機体そのものを覆っている当のパフで、
  上昇させると停滞しているはずの間に判定点の濃さが落ちていく（実測: 上昇させると
  coverage が 0.75 → 0.58 まで下がり、包絡が落ちるより先にしきい値を割っていた）。
  大きさのばらつきも中心だけは上振れのみにする

位置を決め打ちにしても、**大きさは ±35% ばらつかせる**。同じ年齢のパフが全部同じ
半径だと「同じ丸が並んでいる」に見えるため。回転・向き・形の選択も乱数のまま。

### パフの消え方 — 濃いまま停滞し、最後にスッと消える

パフの alpha は、自分の正規化年齢 `u = age / SMOKE_PUFF_LIFETIME`（0 → 1）に対する
**台形**（立ち上がり → 停滞 → 消滅）:

```
envelope(u) = min(1, u / 0.01)                              (u <= 0.90)
            = min(1, u / 0.01) * ((1-u) / 0.10)^1.6         (u >  0.90)
puffAlpha   = SMOKE_PUFF_ALPHA_MAX * envelope(u)
```

```
  1 |    ______________________
    |   /                      \
  0 |__/________________________\__
     0  ↑                    ↑    1
    RISE_RATIO          HOLD_RATIO
```

**当初は `(1-u)^1.3` で直線的に薄れ続ける形だったが、実機で「煙幕を張った」感じが
出なかった。** 出た直後から弱まり続けるので効いている実感が無く、いつ切れたのかも
曖昧になる。濃さを保ってから短い時間で引くほうが、「効いている間」と「切れた」が
はっきりする。

- `u = 1` で厳密に 0 になる。**残留しないし、消える瞬間にぷつりと切れることもない**
  （寿命切れで `alive = false` にするだけの実装だと、まだ見える濃さのまま消えてしまう）
- 立ち上がりは最初の8 tick で 0 → 1。生まれた瞬間に濃いパフが出現するのを避ける。
  撒きの分散と合わせて「湧き上がる」動きになる。**これは寿命に対する割合で持つが、
  寿命を延ばしても短いままにすること**（長いと発煙してから隠れるまで待たされる）
- 停滞は寿命の 90%。ここが「15秒あたりが見えなくなる」当の部分
- 消滅は残り10%（81 tick ＝ 実時間1.7秒）。指数 1.6 は 1.0（直線）だと最後まで
  一定速度で消えて素っ気ないため、落ち始めを緩く・終わりを速くしてある
- 停滞と消滅の境目は連続（`u = HOLD_RATIO` でどちらの式も 1）。段差が出ない

半径は同じ `u` で 30 → 78px へ単調に拡大し、色段も同じ `u` で白 → 淡い紫 → 紫灰へ進む。
つまり**拡散・希薄化・冷却が1つの時計から出る**ので、位相がずれることがない。

隠蔽判定も同じ `envelope(u)` を読むので、**煙が消えるより先に隠蔽が切れることは
あっても、逆（消えたのに隠れたまま）は起きない。** 判定はしきい値越えなので、
目視でまだ薄く見えている状態では既にロックできるようになっている。これは意図した
順序で、「薄くなってきたから狙える」が自機側から読める。ズレの実際の大きさは
「隠蔽判定」の節を参照（描画のほうが濃く出るぶん、判定は保守側に寄る）。

### フォールオフ — 中心を濃く保ち、端で急に落とす

```
falloff(d, r)        = (1 - d/r)^2.5                    (d >= r のとき 0)
puffAlphaAt(d, r, u) = SMOKE_PUFF_ALPHA_MAX * envelope(u) * falloff(d, r)
```

指数 2.5 は「半径の半ばまではほぼ濃度を保ち、そこから外で一気に 0 へ落ちる」形。
ゲーム的にも都合が良く、境界がはっきりするぶん自機側が「どこから先が見えないか」を読める。

**空間の因子と時間の因子を分けているのは、焼き付けと噛み合わせるため。**
`falloff(d, r)` は形なのでスプライトに焼き込み、`SMOKE_PUFF_ALPHA_MAX * envelope(u)` は
`drawImage` 時の `globalAlpha` として毎フレーム渡す。canvas の合成が
両者の積を取るので、上式がそのまま画面に出る。

### 色

パフ1枚の中で色も振る。alpha のフォールオフと同じ停止点に色を載せるので、
実行時のコストは増えない。

- 中心 `#EFEDF5`（ほぼ白、わずかに青紫寄り）
- 中間 `#B4A9C4`
- 端 `#7A7089`（紫がかった灰）

加えて年齢で色が冷えていく。焼き付け方式なので時間変化にも代金が要らない:
**形4種 × 色3段（白 → 淡い紫 → 紫灰）= 12枚を焼き**、各パフは年齢に応じて
隣り合う2段をクロスフェードする（`drawImage` は1パフあたり最大2回）。

**さらに、1枚のパフの中でも瘤ごとに濃さと色を散らす。** 瘤の表は位置と半径のほかに
`a`（濃さの倍率 0.45〜1.0）と `t`（色段のずらし -1/0/+1、隣の段へ半分だけ寄せる）を
持つ。全部の瘤を同じ色・同じ濃さで焼くと、重なりが同心円の膨らみにしかならず、
拡大したときに「大きな丸」に見えてしまう。濃さと色をばらすと、濃い芯・薄い裾・
冷えた縁が1枚の中に同居して煙の塊らしい斑が出る。**焼き付けなので、瘤をいくつ
足しても実行時のコストは `drawImage` 1回のまま**（これがこの方式を選んだ理由そのもの）。

色段のずらしを「半分だけ」に留めるのは、寄せ切ると若いパフの中に古い色の瘤が
混じって年齢が読めなくなるため。

### 絵柄は最初の発煙フレームで焼き付ける

**実装は「起動時」ではなく「最初に発煙が起きたフレーム」で焼く**（`getSmokeSprites()`
は遅延初期化）。モジュールを import しただけでは焼かない。DOM の無い node のテスト
環境で他のモジュール経由で smokeSprites.js が import されても、`document` が無くて
落ちないようにするための遅延実行。128×128 のオフスクリーンへ、瘤の表
（`[{dx, dy, r, a, t}, ...]` を5個 × 4組）から焼く。グラデーションは `falloff` から
生成する。実行時は `drawImage` ＋ 回転 ＋ 拡大 ＋ alpha のみ。

スプライトの一辺はパフの最大直径（78px × 2 = 156px）を下回らせない。下回ると
拡大でぼける。焼くのは一度きりなので、大きくしても実行時のコストは変わらない。

焼き付けを選ぶ理由:

- **形の複雑さの代金を起動時に一度だけ払う。** 毎フレームでは書けない絵柄（瘤の多重合成、
  縁の不規則なほつれ）を、実行時コストは `drawImage` 1回のまま使える。
  パフ1個のコストが形の複雑さと無関係になる
- 毎フレームの `createRadialGradient` が消える（`Map` のレンダーキャッシュと同じ手口）
- 形を4種にするのは、1種を回転させただけだと重なったときに反復が目に付くため
- 瘤ごとに濃さと色を変えられるのも焼き付けの利得。実行時に色を計算すると
  パフ1個あたり瘤の数だけ描画が要るが、焼いてしまえば1回で済む

なめらかなグラデーションを選んだので回転は原理的に見えない。瘤を非対称に置くことで見せる。

## 隠蔽判定

`src/js/utils/concealment.js` の純粋関数:

```
coverageAt(x, y, screens) = 1 - Π(1 - puffAlphaAt(dᵢ, rᵢ, uᵢ))
```

これは `source-over` の合成式（透過率の積、Beer-Lambert）そのものなので、
**判定式そのものは見た目の合成則と同じ形**。canvas のピクセルを読む必要はなく、
GPU と同じ計算を node でテストできる。

ただし焼き付けた**スプライトの実効 alpha**とは一致しない。`smokeSprites.js` の
`_bake()` は瘤を5つ source-over で重ねて焼くため、合成後の実効 alpha は中間半径で
`falloff` より濃くなる（実測。瘤ごとの濃さを 0.45〜1.0 に散らしたあとの値で、
それ以前は 2〜3倍あった）:

| d/r | スプライトの実効 alpha | `falloff(d,1)` |
|---|---|---|
| 0.2 | 0.626 | 0.572 |
| 0.3 | 0.507 | 0.410 |
| 0.4 | 0.351 | 0.279 |
| 0.5 | 0.189 | 0.177 |
| 0.7 | 0.026 | 0.049 |

ズレの向きは「描画のほうが濃い」＝**判定は保守側**（隠蔽判定が使う `falloff` の
値は、同じ位置の描画上の実効 alpha より低い。つまり縁のあたりでは、見た目には
まだ煙が残って見えていても、判定側の coverage はしきい値 0.6 を先に割り込んで
既にロックできてしまっている場合がある）。逆向き（見えているのに判定が
追いつかず、透明なのに隠れている）ではないので実害は薄いと判断し、見た目は
変えていない（低リスクな数値調整を優先する方針。実機での最終判断はユーザー）。

- しきい値 `SMOKE_CONCEAL_THRESHOLD = 0.6` 超えで隠蔽
- 判定点は敵の中心
- **煙の中にいる敵は誰でもロック不能**（artillery 本人に限らない）。結果として護衛効果も出る
- 弾・ミサイルの当たり判定には影響しない。煙は視界だけを遮る

### 守るべき対: フォールオフは1つの関数から

**焼き付けるグラデーションの停止点は `falloff()` から生成し、描画時の `globalAlpha` と
隠蔽判定はどちらも `puffAlphaAt()`（= `falloff` × `envelope`）を呼ぶ。**
どこか1箇所だけ数式を書き直すと「濃く見えるのに隠れない」「薄いのに隠れる」「消えたのに
判定が残る」がすぐ発生する。`renderWeaponSound` と `renderWeaponProfile` を対で扱う
既存のルール（CLAUDE.md）と同じ扱いにする。

ただしこの共有で揃うのは**瘤1個ぶんの停止点**まで（`tests/smoke-sprite.test.js` が
縛っているのもそこ）。スプライトは瘤を5つ重ねて焼くので、合成後の実効 alpha は
上表のぶんだけ判定より濃い。**「同じ関数を呼んでいるから画面と判定は同一」とは
言えない**ので、瘤の並び（`SMOKE_SHAPES`）を触ったときはこのズレの大きさが
変わることを意識すること。

## Auto Aim への接続

`main.js` の `_updateAutoAim()`（`src/js/main.js:821`）に2箇所:

1. 候補走査（`for (const enemy of this.enemies)`）で、隠蔽されている敵を飛ばす
2. ロック中の敵（`autoAimLockedEnemy`）が隠蔽されたらロックを落とす

自機の弾やクロスヘアの手動照準には手を入れない。

`src/js/audio/weaponSounds.js` の `WEAPON_SOUNDS` に `smoke` を1行足す。
hiss ベースの短い噴出音。位置つきで再生（`AudioManager.setListenerView` の定位に乗る）。

## 描画とライフサイクル

- 更新: `particles` と同じ場所（`main.js` の更新ループ）で `smokeScreens` を回し、寿命切れを外す

## 定数（すべて `src/js/utils/Constants.js`）

```

SMOKE_RING_INNER          = 0.42  // 内側の列の距離（基準に対する比）
SMOKE_RING_OUTER          = 0.85  // 外側の列
SMOKE_PUFF_RADIUS_JITTER  = 0.35  // パフごとの大きさのばらつき（±この割合）
SMOKE_GROWTH_RATE         = (RADIUS_END - RADIUS_START) / LIFETIME   // 導出
SMOKE_DRIFT_RATIO         = 0.5   // 成長に対する漂いの速さ。1 を超えさせない
SMOKE_DRIFT_SPEED         = SMOKE_GROWTH_RATE * SMOKE_DRIFT_RATIO   // 導出
SMOKE_RISE_SPEED          = 0.02  // ゆっくり上昇
SMOKE_SPRITE_SIZE         = 256   // 焼き付けるスプライトの一辺。パフ最大直径(270px)を下回るとぼける
SMOKE_SPRITE_SHAPES       = 4
SMOKE_SPRITE_TINTS        = 3
```

### 拡散はパフ自身の成長より遅くする（実装時に判明）

**漂いが成長を追い越すと、煙がまだ濃いうちに雲がばらけて判定点の重なりが崩れ、
隠蔽が短くなるうえ走るたびに揺れる。** これがこの機能でいちばん壊れやすい関係。

当初の値（drift 0.10）ではパフが寿命のあいだに 24px 外へ散り、パフ自身の成長
（16 → 34px ＝ 18px）を追い越していた。隠蔽が続く時間が実測で中央値 48 tick
（要求は 60 超）しかなく、撒き位置の乱数で毎回 45〜80 tick と大きくばらついた。
alpha を上げると中央値は伸びたが**ばらつきは残った** — alpha は寿命のどの時点にも
一様に効くだけで、「散って重なりが崩れる」構造そのものは変わらないため。
drift を下げて成長より遅くしたときに、持続もばらつきも同時に解決した。

**この関係は実数で持たない。比で持って式に守らせる。**

```
SMOKE_GROWTH_RATE = (RADIUS_END - RADIUS_START) / LIFETIME
SMOKE_DRIFT_SPEED = SMOKE_GROWTH_RATE * SMOKE_DRIFT_RATIO   // RATIO < 1
```

px/frame の実数で持っていたときは、下の3回とも手で追随させる必要があった。
とくに3行目が罠で、**半径を触っていないのに寿命を変えただけで成長が 1/4.5 になる。**
drift を据え置くと、停滞しているはずの20秒のあいだに雲が 151px 外へ散って、
濃さが残っているのに隠れなくなる。

| きっかけ | 半径 | 寿命 | 成長 px/frame | drift |
|---|---|---|---|---|
| 最初 | 16 → 34 | 240 | 0.075 | 0.05 |
| 実機で「小さい」 | 30 → 78 | 240 | 0.20 | 0.14 |
| 実機で「20秒停滞させたい」 | 30 → 78 | 1080 | 0.044 | 0.025 |
| 実機で「扇形に」 | 46 → 100 | 1080 | 0.05 | 0.025 |
| 実機で「15秒に」 | 44 → 100 | 810 | 0.069 | 0.035（導出） |

比にしてからは、半径も寿命も自由に触れる。上昇（`SMOKE_RISE_SPEED`）は
これに縛らず実数のまま持つ。浮力は煙の大きさとは別の性質で、寿命が延びれば
そのぶん高く昇るのが自然なため。

## 実機で確認してもらうこと

ハードリロード（Cmd+Shift+R）が必要。

| 見るところ | 調整用の定数 |
|---|---|
| 煙が濃すぎる / 薄すぎる | `SMOKE_PUFF_ALPHA_MAX`、`SMOKE_PUFF_COUNT` |
| 境界がぼやける / 硬すぎる | `SMOKE_FALLOFF_EXPONENT` |
| 隠れる範囲が広すぎる / 狭すぎる | `SMOKE_PUFF_RADIUS_END`、`SMOKE_CONCEAL_THRESHOLD` |
| 停滞が長すぎる / 短すぎる | `SMOKE_PUFF_LIFETIME`（実時間の秒数 = 値 ÷ 60 ÷ 0.8 × `SMOKE_PUFF_HOLD_RATIO`）。漂いは導出なので追随する |
| 消え方がだらだらする / 唐突すぎる | `SMOKE_PUFF_HOLD_RATIO`（下げると消滅に時間をかける）、`SMOKE_PUFF_DECAY_EXPONENT` |
| 発煙が頻繁すぎる | `SMOKE_COOLDOWN` |
| 湧き上がって見えない | `SMOKE_EMIT_SPAN` |
| 発煙直後なのに隠れない | `SMOKE_RING_INNER` を下げる（中心の重なりが増える）、または `SMOKE_PUFF_RADIUS_START` を上げる |
| 扇形の広がり方を変えたい | `SMOKE_ARC_FROM_HOUR` / `SMOKE_ARC_TO_HOUR`（時計の文字盤）、`SMOKE_RING_INNER` / `SMOKE_RING_OUTER`、`SmokeScreen.js` の `EMISSION_RINGS`（枚数。**`SMOKE_PUFF_COUNT` と合計を揃える**） |
| 列が点の並びに見えて壁にならない | `SMOKE_PUFF_RADIUS_START` を上げる（列の間隔より大きく） |
| 同じ丸が並んで見える | `SMOKE_PUFF_RADIUS_JITTER` |
| 回転が揃って機械的に見える / 渦に見える | `SMOKE_ROTATION_SPEED`、`SMOKE_ROTATION_JITTER` |
| 紫が強すぎる / 弱すぎる | `smokeSprites.js` の `SMOKE_TINTS` |
| 煙の縁なのにロックできてしまう | 副瘤の `r` か `a` を落とす（`SMOKE_SHAPES`）。描画は瘤を5つ重ねる分、判定（`falloff` 単体）より濃く見えるため、縁は見た目にはまだ煙が残っていても判定側は先にしきい値を割ってロック可能になっている |
| 煙が小さい / アタッカーを隠し切れない | `SMOKE_PUFF_RADIUS_START` と `SMOKE_PUFF_RADIUS_END`。上げたら `SMOKE_DRIFT_SPEED` が成長より遅いままか、`SMOKE_SPRITE_SIZE` がパフ最大直径を下回らないかも確認する |
| 1枚が「大きな丸」に見えて煙らしくない | `SMOKE_SHAPES` の瘤ごとの `a`（濃さ）と `t`（色段のずらし）の散らばりを強める、または瘤を増やす |

## やらないこと

- 煙が敵側の射線を遮ること（artillery は煙の中からでも撃てる）。煙を張る利得が
  「逃げる間の時間稼ぎ」だけになってしまうため
- ミニマップからの消去。まずは目視と Auto Aim だけで様子を見る
- 雲ごとの濃度上限（オフスクリーン合成）。素直な重ねで足りると判断
- 風で流れること
- 寿命後半の色の冷えを2組の種の差し替え以上に凝ること（実機で物足りなければ足す）
