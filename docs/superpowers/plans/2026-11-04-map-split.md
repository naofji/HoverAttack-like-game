## 各段の手順（1段 = 1コミット、後ろの層から）

1. 移す範囲を**メソッド名で**切り出す（行番号は前の段で変わるので、毎回 `grep -n '^    名前('` で取り直す）。
   切り出しは使い捨てのスクリプト（python）で、宣言行からその次のメソッドの直前の JSDoc までを1塊として動かす。
   **コメントは一字も変えない**。メソッドの間のセクション見出しのコメントも、先頭のメソッドに付いて動く
2. 新しいファイル: 冒頭のコメント（何を持つか・`Map.prototype` へ混ぜる前提・`Map.js` を import しない）、
   使う定数・関数の import、`export const MapXxx = { … };`。class のメソッドは字下げ4のままリテラルのメソッドになる。
   メソッドの間には `,` が要る
3. `Map.js`: import を足し、ファイル末尾（`export { BLOCK_EMPTY … }` の前）に `Object.assign(Map.prototype, MapXxx);`。
   `Map.js` で使われなくなった import は消す（`node --check` では分からないので grep で確かめる）
4. 検証:
   - `npm test` → 2834 / 2795 / 38 / 1 と同じ
   - `node tools/trace-map.mjs > after.json && node tools/trace-map.mjs --compare before.json after.json` → IDENTICAL
   - メソッド集合の照合（基準の `git show 29f8ae8:src/js/world/Map.js` と、分割後の全ファイルの和）が一致
   - 段2以降は `tests/map-mixins.test.js`（段1で作る）が通る
5. コミット（`git add` はファイルを明示。`main.js` は add しない）

## 名前の衝突テスト（段1で作り、段ごとに mixin を足す）

`tests/map-mixins.test.js`: すべての mixin のリテラルを import し、
(a) mixin どうしでキーが重ならない (b) `Map.js` の class 本体のメソッドと重ならない
(c) 混ぜた後、各キーの `Map.prototype[k] === mixin[k]`（後から上書きされていない）。
(b) は class 本体のメソッドを `Object.getOwnPropertyNames(Map.prototype)` から mixin のキーを除いたもので取ると恒真になるので、
**`Map.js` の class 本体を持たない**形では確かめられない。代わりに (c) で「混ぜた値が残っている」ことを見る
（class 本体の同名メソッドは Object.assign で上書きされるので (b) の衝突は (c) では見えない → (b) は
メソッド集合の照合（段ごとの検証）で拾う。重複があれば和集合の要素数が基準より減る）。
確認: 2つの mixin に同じキーを置くと (a) が赤くなること
